# 1. Released performance and scaling

- **Doing:** confirm0.5.4 at its tag, then test which memory traffic or finishing cost binds the i9 plateau.
- **In order to:** 0, put correct measured speed in users' hands.
- **0.5.4, released:** #537 trims by mode on the measured i9: unpinned lazy7/28 from10t; pinned one CPU per requested core also lazy6/24 at8t, eager5/20 at6t and eager3/12 at4t. #545 reads machine facts once per process after repeated sysfs reads caused a small-input regression in the first release check. Replacement four-core CI found no slower row, but wide intervals. Tag scaling and crossover queued, not yet judged ([release](https://github.com/lmmx/mibz2/pull/145#issuecomment-6952096740)).
- **0.5.3 result and correction:** #524 shipped lazy7/28 from10t on the i9. Release scaling versus0.5.2: 12–20t wall about−6.5%, CPU−25%, RSS−22%. At10t the harness's pin mask hid the trim, so that release row measures an unchanged plan. Unpinned explicit-arm10t7/28 over10/40 wall0.873 [0.866,0.880]; pinned 0.881–0.889. Lower-count unpinned trims did not qualify, although pinned ones did ([release](https://github.com/lmmx/mibz2/pull/145#issuecomment-6946439743), [scaling](https://github.com/lmmx/mibz2/pull/145#issuecomment-6946756938), [unpinned](https://github.com/lmmx/mibz2/pull/145#issuecomment-6949008682)).
- **Plateau:** 0.5.3 crossover found no team arm faster than shipped at4–20t and the plateau around8–9t. Unpinned knee diagnostic: workers93–95% busy; front end, window and consumer ruled out as starvation sources; L3-miss reads per output byte rose with worker count. Main-memory saturation unconfirmed because IMC counters unavailable. Pinned lower-count tests partly measured front-end competition ([crossover](https://github.com/lmmx/mibz2/pull/145#issuecomment-6947191226), [knee](https://github.com/lmmx/mibz2/pull/145#issuecomment-6948385717)).
- **Negative arms:** fused finishing pass missed its Holm bar and was NOT ADOPTED despite an indicative1.5% point gain. Stop-and-walk also NOT ADOPTED. Neither becomes a production default by reinterpretation ([fused](https://github.com/lmmx/mibz2/pull/145#issuecomment-6947507581), [walk](https://github.com/lmmx/mibz2/pull/145#issuecomment-6922810916)).
- **Earlier releases:** 0.5.2's one-fewer-worker plan preceded0.5.3; 0.5.1 added lazy workers at10 and capped workers past physical cores. 0.4.0 brought Cells buffer reuse and the breaking Kernels soundness fix. Their own frozen verdicts stay in the linked record ([0.5.1](https://github.com/lmmx/mibz2/pull/145#issuecomment-6912414999), [0.4.0](https://github.com/lmmx/mibz2/pull/145#issuecomment-6900382325)).
