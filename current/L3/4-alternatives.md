# 4. Alternative decoder architecture

- **Doing:** investigate what could move the new ten-core Workers/Teams threshold further.
- **In order to:** 0, improve the released decoder across its high-thread regimes.
- **Empirical threshold:** valid i9 run found independent Workers faster at6–9t but Teams faster at10; Louis adopted Teams from10 despite nine-thread CPU+12.4% versus the registered10% flag. This establishes a policy for that machine, not the cause of the crossover ([run](https://github.com/lmmx/mibz2/pull/145#issuecomment-6896798131), [choice](https://github.com/lmmx/mibz2/pull/145#issuecomment-6896854245)).
- **L3 capacity hypothesis:** summed median Cells working set rises roughly13.6,15.9,18.2,20.4,22.7MiB from6–10 workers against an i9 20MiB shared L3; the Workers advantage shrinks then flips. This five-point pattern and earlier dose sensitivity motivate a smaller-block build, but cache misses were not measured and DRAM bandwidth is a competing explanation. Coordinator registered an under~1.8MiB/block aim and an i9 decision rule after CI ([assignment](https://github.com/lmmx/mibz2/pull/145#issuecomment-6897826122)).
- **Proposed layout withdrawn before a build:** MONODROMY first priced a 16 B top slot plus12 B rule at median1.78MiB. Reading the writer showed short-factor lengths needed extra arena bytes or unsafe high-bit packing on forced routes; corrected estimate is about1.84MiB, with only a few blocks below1.8. The already CI-rejected 16 B top slot alone reaches median1.90 and31/196 blocks below1.8. No cheap layout met the target; MONODROMY did not start a build. Its suggested small/large-buffer test is unregistered in the covered channel ([first estimate](https://github.com/lmmx/mibz2/pull/145#issuecomment-6897885393), [correction](https://github.com/lmmx/mibz2/pull/145#issuecomment-6897897097)).
- **Other bounds:** #410's current-tree compulsory traffic floor at modelled5MiB survives a correction to earlier non-realizable reorder examples; it does not bound a different layout or prove the new L3 hypothesis. Equal-cell elision #418 and writer #407 closed on slower builds; earlier Cooperative Cells at4 cores lacked a compute case. The threshold result does not itself qualify a new high-thread construction ([locality](https://github.com/lmmx/mibz2/pull/145#issuecomment-6894415432), [elision](https://github.com/lmmx/mibz2/pull/145#issuecomment-6895882037), [writer](https://github.com/lmmx/mibz2/pull/145#issuecomment-6894223006)).
