The one-thread workstation comparison's preparation is integrated but no run has occurred, and Louis's detailed technical companion has merged into site source without verified deployment. The live decoder diagnostic still needs the causes of two unresolved hosted checks and verified workstation inputs; a separate Rust compatibility correction has now merged and passed its post-merge tests, without producing a speed result.

## What is ready, and what is still waiting?

The earlier [one-thread comparison](https://github.com/lmmx/mibz2/pull/145#issuecomment-6782294636) asks whether an inlining change recovers speed against 0.2.9. Its memory-accounting check initially failed because of inherited accounting assumptions, not a demonstrated decoder fault. The Guardian [accepted the corrected accounting](https://github.com/lmmx/mibz2/pull/145#issuecomment-6790889882) for those paths after independently replaying the traces. The corrected repair was then appended to the existing [comparison branch](https://github.com/lmmx/mibz2/pull/366), preserving its candidate, baseline and ten-pair rule. Its seven Actions and legacy check are now green. One secondary random-input case is 3.3% slower in the paired bench; the Coordinator kept that result and recommended a separate, deliberate integration as diagnostic preparation, without calling it a production speedup. The Coordinator's deliberate [integration merged this preparation](https://github.com/lmmx/mibz2/pull/145#issuecomment-6831115741) into master without claiming a new speed gain. The separate accounting-repair branch was closed as incorporated, so the repair was not applied twice. No ready job has been queued and no workstation result exists.

The [new diagnostic harness](https://github.com/lmmx/mibz2/pull/373) addresses a different question. Untimed checks show it can run the actual decoder reader, compare instrumentation off and on, and retain output and error parity. The intended later programme has ten paired rounds across three corpora and two instrumentation modes, with 120 measured decodes and nine preliminary checks. Those measurements have not run. The [independent review](https://github.com/lmmx/mibz2/pull/145#issuecomment-6821626797) found that failed child processes could lose wall time, CPU time and peak memory already collected. Codex [corrected that path](https://github.com/lmmx/mibz2/commit/b5131679f51c2a0245bc03f62b7afd833b8bff23): resource data is saved before a failed run is rejected, while failed rows stay out of successful estimates. The Coordinator [accepted the correction](https://github.com/lmmx/mibz2/pull/145#issuecomment-6822234208) after three focused mocked tests, without treating them as decoder timing. After the integrated accounting base was [added to this branch](https://github.com/lmmx/mibz2/pull/145#issuecomment-6831115741), [preparation, tests, memory accounting and benchmark workflows passed on its new head](https://github.com/lmmx/mibz2/commit/ed6f424f238851ff8296e7a48c2b96dfb8332e7e/checks). These checks include the ordinary and team accounting assertions that previously failed. The macOS ARM build passed, but the x86_64 packaging job was cancelled without recorded steps; its log was unavailable and four check annotations have not been retrieved. The [hosted legacy code check failed](https://api.github.com/repos/lmmx/mibz2/commits/ed6f424f238851ff8296e7a48c2b96dfb8332e7e/status), but its output was inaccessible, so the cause is not known. A [pinned recovery note](https://github.com/lmmx/mibz2/pull/373#issuecomment-6838120361) asks an operator with access for the complete hook output and all four annotations, so the failures can be classified separately before a targeted recovery. A successful benchmark workflow is a check of the harness, not evidence that the experimental decoder is faster. There is also a newly checked handoff gap: the diagnostic recipe requires a processor choice and test inputs, while the workstation queue passes only a recipe name. Those choices must be fixed in a runnable recipe before a queue entry can be admitted.

## What did the research establish?

A registered workstation run measured the cells inversion stage at about 82% of the current stage's time, but the experimental whole Wikidata decoder was level. Codex's [all-block census](https://github.com/lmmx/mibz2/pull/145#issuecomment-6782495828) found that the new route admits 84.117% of Wikidata rows, so refusal alone is unlikely to explain the missing gain. The first cells implementation's specific safety objection was independently resolved, yet its corrected head failed the pre-set default-performance condition and remains unmerged. The corrected harness is meant to price the live reader and inversion work; it has not established a cause or a gain. Its checks so far do not cover an injected panic, and a count of initialized bytes is not a count of physical memory traffic.

A separate phrase-level idea passed a bounded traversal screen on one real block but [failed its metadata budget](https://github.com/lmmx/mibz2/pull/145#issuecomment-6808483473), so that representation is not a candidate for compiled-cost timing as built. Later saved-trace pricing retained a compact global pass as a comparator, called for revision of selective batching, and stopped standalone origin optimisation on current evidence. These are research dispositions, not production changes. The proposed extra comparison of a warmed-up reconstruction stage is still a separate, unadmitted programme; it has not been added to the live-reader harness.

A separate [small compatibility change](https://github.com/lmmx/mibz2/pull/375) lets an existing packet-census example pass a new Rust compiler lint without changing the mathematical walk it checks. Its author reran the exhaustive validator and obtained byte-for-byte identical archived results. The full project check then found the same lint in a different, unchanged move-to-front example. Codex [delivered that bounded correction](https://github.com/lmmx/mibz2/pull/145#issuecomment-6836435433), and the Coordinator [accepted its scoped delivery](https://github.com/lmmx/mibz2/pull/145#issuecomment-6836501333). The revised loop traverses the complete array in the same order and preserves its arithmetic; the packet fix remains unchanged. The author reports passing Rust 1.100 full-project lint and format checks, 136 untimed synthetic comparisons and seven production move-to-front/checkpoint tests. An optional all-feature test could not link against a missing local Python library, so it is no pass. The final exact-head tests, packaging and legacy check all passed. Under Louis's separate authorisation, Codex [merged the correction](https://github.com/lmmx/mibz2/pull/145#issuecomment-6838153034) at the expected head, and GitHub independently confirms that merge. Post-merge tests and documentation build/deploy-branch checks passed; the ordinary non-release packaging push was skipped. These checks do not establish a decoder speedup or a release. This is maintenance of research checks, not a new decoder speed result or a reason to relax the integration gate.
