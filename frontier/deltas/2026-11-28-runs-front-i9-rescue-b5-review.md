**What was asked:** An independent, adversarial B5 memory-safety review of the `unsafe` AVX2 code PR #1238 adds to `src/runs.rs` (`front_avx2` and its use of `second()` and `STEPS`), as `runs-front-i9-rescue`'s `done_when` requires. This review reserves nothing on the claim and does not hold it.
**Verdict: PASS, with no changes required.** I could not construct an out-of-bounds read or write, an uninitialised read, a misaligned access or an aliasing violation. Each implementer claim below was rechecked against the code, not taken from the deltas.
- **Gating:** `front_with_syms` calls `front_avx2` only when `front_fast(k)` holds: `k.avx2`, which only `Kernels::detect`, the narrowing `restrict` or the `unsafe` `new_unchecked` can set, plus runtime BMI2, LZCNT and POPCNT detection. `second()` is `#[inline(always)]` and is called only from inside the `#[target_feature]` function. The diff leaves this dispatch unchanged.
- **Pass 1 bounds:** `m < 2^24` is checked first. With `words = m/64 + 3`, the 64-symbol loop runs only while `wi < m >> 6`, so its four `loadu` reads stay inside `syms[..m]`. The tail reads `rem = m - 64*wi` symbols. The highest word written is `wi + 1`: at most `m/64 + 1` when the end-of-block symbol is found in the loop, and `n64 + 2` after the tail. Both are below `words`. `set_len(wi + 2)` covers only words that were written. `m = 0` neither dereferences nor offsets the dangling pointer. At `t == 63` the keep mask is built by hand, which avoids the `2 << 63` underflow.
- **Pass 2 reads:** every `lit` bit is below `end`, because the end-of-block word is masked with `keep >> 1` and the tail stops at the end-of-block symbol. So `spw.add(tz)` stays below `end < m`, and `seek!` and `after` read words only up to `last = end/64`. `count!` starts at `from <= end` and reads 8 unaligned bytes, ending at byte `8*last + 14 < 8*(last + 3) = 8*len`. `q2 - q <= 22` holds before `_bzhi_u64`.
- **Records:** capacity is `m + slack + 2`. A literal writes one record, at most `end - 1 < m` of them. The opening run writes one. Every record past the first in a run longer than 127 rows is taken off `slack`, and the kernel returns `None` once `slack` would go negative. Every record length is between 1 and 127, and each byte's records sum to `cnt[c]` (`total >= 1` because the closing literal's or end-of-block symbol's bit is set in `one`). These are the invariants `fill_avx2_trusted` relies on when `trusted && n == len`. On `None`, `runs.len` stays 0, `counts` are untouched and `trusted` is false.
- **The `[u32; 256]` counts cannot wrap:** short runs give at most `(2^24 - 1) * 127 < 2^31` rows, and long runs at most `big <= max_len < 2^31` rows, both checked before the add. Indexing comes from a `u8` and is bounds-checked safe code.
- **`second()` and `STEPS`:** `MaybeUninit<AlignedRows>` (64-aligned) is fully initialised by `copy_nonoverlapping` of 224 bytes before any read. Its index is `(s-1).min(255) - 32 < 224`, including `s >= 0x8000`. `Step` is `repr(C, align(64))`, so `a`, `b`, `c` and `d` are 16-aligned for `_mm_load_si128`, and `s - 1 < 32` stays within `STEPS`. Pass 1 tests `s <= 1` as `(s >> 1) == 0`, which is exact for every `u16`.
- **Aliasing:** the raw pointers into `lit`, `one` and `runs` belong to separate allocations, and none of them is reallocated after its `reserve`. `tail` is accessed only through its raw pointer. `syms`, rather than `b.syms`, is used consistently, as the `scan-oracle` build requires.
