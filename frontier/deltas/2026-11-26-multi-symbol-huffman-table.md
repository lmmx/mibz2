**What was asked:** Prototype 4-byte packed `K = 3` (24 KiB/6 tables) and 8-byte `K = 4` (48 KiB/6 tables) 10-bit root Huffman tables with runt selector gating against a faithful copy of shipped `K = 2` (`src/huff.rs`), verify byte-identical symbols on all 431 blocks of `corpora/wikidata.bz2`, and evaluate the frozen ≥8% A3 non-overlapping stop test over 7 interleaved repeats.
**What I found:** **Verdict: STOP.** All 11 arms verified 100% symbol- and end-bit-identical on all 431 blocks (24,979,299 symbols; `sym256 = 0`) plus synthetic `alpha = 258` edge cases, reproducing `huff_lookup_census.rs` lookup cuts (`K = 3`: −12.39%, `K = 4`: −15.38%). Yet neither clears the ≥8% A3 gate on this 2-vCPU Haswell Xeon (32 KiB L1d / 256 KiB L2, matching i9-10900K L1d/L2):
- **Baseline x86-64 (default release, 7 interleaved repeats, all 431 blocks):** `k2_shipped` med **76.852 ms** (`75.457–78.500`; 5.744 ms tables + 67.726 ms decode, 2.710 ns/sym full). `k3_4b` **78.882 ms** (+2.64%, non-overlapping slower), `k3_4b_gated` (`n_sel >= 64`) **78.869 ms** (+2.62%), best `k3_4b_batch5` **77.692 ms** (+1.09%, overlapping). `k4_8b` **91.432 ms** (+18.97%) and `k4_8b_gated` **90.421 ms** (+17.66%, non-overlapping slower).
- **Native build (`-C target-cpu=native`, BMI2 `shlx` + AVX2):** `k2_shipped` med **67.699 ms** (`65.720–69.863`, itself −11.9% faster than baseline!). Best `k3_4b_batch5` **66.970 ms** (−1.08%, overlapping), `k3_4b_gated` **67.148 ms** (−0.82%), `k4_8b_gated` **77.588 ms** (+14.61%, non-overlapping slower).
- **Why `K = 3` loses even inside 24 KiB L1d:** (1) Group-boundary tail amplification (`GROUP - 3*5 = 35` vs `40`; 97.3% of groups hit `k = 48` or `49` vs 43.9% in `K = 2`) caps even the zero-store `nostore` oracle at **−6.06%** baseline / **−6.19%** native (already below 8%). (2) Branchless 3-symbol writes execute +31% more store+extract uops, doubling store+extract overhead (`0.134 -> 0.258 ns/sym`, +3.1 ms baseline). (3) Pass-3 builds add `+1.71 ms` gated (`7.450` vs `5.744 ms`; gating saves `0.50 ms` on the 198 runts, max `n_sel = 20` vs min full `1,413`). (4) `K = 4` spills 32 KiB L1d (`+8.9%..+14.3%` decode) and doubles table builds (`11.4–12.0 ms`).
