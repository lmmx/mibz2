# Full worker

The 32×32 pair's absolute native time is close to the fastest observed stock control and faster than the stock image in the same second binary. The same stock source changed materially between native panels. This motivates verification in actual complete workers and scrutiny of toolchain, allocation and code placement.

Use the existing research-only symbol hook and frozen scalar-cap inverse. Blocks below 64 symbols continue directly through the original front, since no complete bitmap word is required for those. For a larger run-route block, a validated private front yields all records, counts and length. The complete original scalar-cap admission, marked inverse, RLE1 and CRC follow. On an invalid symbol stream, primary, ineligible CPU, or an inverse gate rejection, decline and let the original decoder perform its normal checks. A sufficiently large dense rejected block therefore pays for both fronts and may retain both scratch sets. Include this in the stock-front copy control and true-corpus whole-worker pricing. The 64 KiB permutation table is shared read-only. Each worker has a private second record/bitmap state and 2048 extra counter bytes. The actual high-water RSS decides memory viability.

Freeze three distinct decoder images from a common scorer projection: original scalar, copied stock front + scalar, 32-rank paired front + scalar. Gate the new worker with libbzip2 and the scorer. If the full front/worker comparisons warrant, collect 18 paired W1 and W4 whole-corpus samples (six round-rotations of the three arms), one prewarm per worker, 2s settles. Report relative to both comparators, all memory ratios and source + binary hashes. A close local effect feeds independent CI consideration. A candidate below 1.0 versus the slow copied stock control alone cannot claim a gain over scalar.
