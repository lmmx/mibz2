# Adjacent nonzero MTF ranks

Frozen decoder is the scalar-cap worker at `d0a42980e896211906234c7679b38760ae44a46e`. Its MTF run front is AVX2 on this host. MTF's two-level list (#207, merge bc899400) already keeps the first 32 bytes in two registers. Run-front production (journal 2026-11-10, source SHA-256 in generate.py) already builds two symbol bitmaps and jumps between consecutive literal positions. Short-run stores (#170, e7c30a86) change the column path. This experiment concerns the permutation between two literal-bit positions in the record path. The intervening RLE2 digits repeat the first byte and leave the list invariant.

For a literal of symbol s the rank is i=s−1≥1. Let L be the first sixteen bytes of the old list. A move at i sends destination k to source i if k=0, to k−1 if 1≤k≤i and to k otherwise. Compose these two destination-to-source maps in reverse order. For any two nonzero ranks i,j<16 the new low bytes are [second output, first output]. The first selected byte moves from slot zero to slot one when the second selection is made. The second register and tail are unchanged. The conclusion applies to arbitrary bytes including repeated byte values. A 16×16 table of aligned 16-byte masks occupies 4096 immutable shared bytes; the 225 valid rank pairs occupy 3600 bytes. No worker scratch changes. One shuffle and one 32-bit extraction give both bytes. The old count logic still gets the exact old two spans, in order, and executes both ordinary cap/counter stores. Since the first literal is paired only with a literal later in its bitmap word, cross-word and final lookahead need no speculative read.

Cheapest structural test. Census all possible consecutive low ranks among literal positions of each run-admitted block. Compare within-word choices with input-adjacent and unrestricted matching at the same threshold. Reject if the active update fraction is below one-quarter. The 383 record routes out of 431 carry 15,147,621 literals and support 5,860,671 disjoint pairs, covering 77.38%. The other 48 use the unchanged column route.

Paid test. Run all 383 actual fronts in stream order, with original bitmap construction, two-level high ranks, cap records, per-byte rows/records and scalar fallback checks against independent scalar-front outputs outside the timed region. Compare three generated native copies from one pinned source. The single specializes a low rank to one shuffle without changing ordinary emission or the number of updates. The pair adds within-word pairs and keeps that single specialization otherwise. Use 36 rounds, all six arm orderings equally often, warm reused scratch, one full corpus lap per sample, paired log-t intervals. Independent references are a single raw scalar forward scan and the unaltered original decoder. A stage win warrants the original full worker and libbzip2 gate including malformed inputs as well as scalar-cap matched timing. A close estimate cannot establish i9 performance. Record negative evidence when entry counts save work but additional branches cost more than the saved permutation.

The first panel made the rank-16 division expensive even without composition. Extend the tested pair domain to both resident registers (ranks 1–31) and restore the exact original stock fallback for unpaired literals. A four-mask table with 1024 cache-line entries uses 64 KiB. The combined validity test uses a bitwise OR of the two ranks. This composes 7,311,529 pairs (96.54% of all literals). Price whether saving a pair of list updates now pays for the larger shared table, second count, bit consumption and pair/word branches. Repeat all six arm orders, 36 rounds with stock, original 16-rank pair and candidate, with the same corpus and exact fixtures. A loss on both domains retires this greedy within-word formulation.
