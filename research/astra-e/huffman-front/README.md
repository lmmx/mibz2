# A fused Huffman and MTF record producer with free authenticated boundaries

On the complete 431-block Wikidata input, the best fused arm used **1.1336 [1.0638, 1.2079]** times the shipping Huffman-plus-front CPU. Giving a worker authenticated block boundaries for free, avoiding the full symbol tape on eligible blocks and preserving the existing canonical two-symbol lookup did not repay the new tiled MTF/RLE2 construction. The independently verified scalar-cap worker remains ahead. [Native observations](panel.csv) · [All estimates and capacity measurements](results.json)

The actual boundary finder previously tested in #317 at `efc1bd88c73b07d917617eddfdf008dffc691e3d` still parsed Huffman into a symbol vector before calling the worker. On the i9 its level-9 Wikidata throughput was 1.006 of the original scan path at W8 and 0.981 at W10; level-1 at W10 improved to 1.615. The compact30 proposal describes fusing Huffman and MTF at the worker, and pbz2 shipped a differently integrated path into a T-vector. Those results leave the same-capped-record computation open. [Pinned prior work and target accounting](evidence/README.md)

Every arm starts at the same authenticated compressed bit and gets only the stream level. All parse the header, byte map, selectors, code lengths and canonical Huffman tables. The stock arms materialize the normal symbol vector and run the shipped MTF front on either the record or column route. The fused arms keep a maximum working tile of sixteen 50-symbol groups, carrying the MTF registers, high tail, opening byte and any unfinished little-endian RLE2 digits across tile boundaries. The 50-symbol arm flushes every selector group. The 800-symbol arm flushes every sixteenth. They return identical capped records, row counts and record counts. One run bit per input symbol supports the *original* evenly sampled admission after EOB, including the EOB position in the denominator. A rejected fused parse or route invokes the stock parser again from its original bit and completes the actual original front. [Frozen design](PLAN.md) · [Generator](generate.py) · [Fused record producer](front.rs)

Both constructors accepted all 383 real record routes and declined the 48 small column routes. Their metadata, ending bits, ordered cap records, both counters and fallback columns matched the controls on all 431 blocks. Rebuilding the marked inverse from the returned column, expanding RLE1 and checking block CRC recovered all 209,700,196 libbzip2 plaintext bytes. The reference scanner checked combined stream CRCs. Another 1,612 clean, truncated or mutated compressed-item cases agreed in validity, error kind and accepted front output. Of these 1,086 invoked genuine fallback. This is a test of the compressed block envelope and front; discovery, speculative errors in an asynchronous worker and stream-delivery ordering were out of scope. [Per-block byte and CRC evidence](checked.csv) · [Malformed inputs](adverse.txt)

Across 24 paired native complete-corpus rotations, the 50-symbol arm cost **1.2205 [1.1101, 1.3419]** of the shipping library's work, the 800-symbol arm **1.1336 [1.0638, 1.2079]**, and the copied canonical-parser control **0.9609 [0.8989, 1.0272]**. Median times were 144.6 ms for the library, 143.8 ms for its copy, 182.6 ms for the smaller tile and 168.8 ms for the larger tile. Each lap initialized per-block state, reused real scratch between blocks, and finished all 383 record fronts and 48 column fallbacks. The claim is native thread CPU on the local Xeon.

A second binary held the replacement record constructor fixed and charged either full input-symbol materialization or interleaved delivery. Materialized Huffman plus the same 800-symbol MTF front cost **1.1657 [1.1374, 1.1948]** of the shipping two stages. Interleaved/materialized cost **1.0260 [0.9959, 1.0571]**. Both produced the same block CRC-checked bytes. This identifies substantial cost in the chosen record producer independent of the saved symbol tape. It leaves other front algorithms open. [Eighteen paired rotations](split.csv) · [Matched attribution generator](attribution.py)

All three direct arms needed a stock 1,800,200-byte symbol vector once a real block declined. On one worker processing all envelopes in order, the peak retained vector capacities were 3,564,672 bytes for original and 3,519,800 bytes for the fused arms. Each included the 900,000-byte column fallback reserve. The 800-symbol producer allocates a fixed 864-u16 stack tile (including guard words), the MTF state and counters. Stack scalars, code tables, compressed input, queues, allocator residency and RSS are outside those capacity totals. Different distributions of false or fallback blocks across workers would change the high-water marks. [Sequential capacities](memory.csv)

To reach the target on the 40-round independent i9 receipt, transferring the measured historical role proportions to the verified scalar worker would require optimistic x4 aggregate CPU savings of about 169, 139, 107 and 13 ms at W7, W8, W9 and W10 respectively. On the 48-round data, the corresponding values are 174, 141, 91 and 0 ms. The inferred W10 floor changes between receipts. These requirements assume zero-cost discovery and scheduling, with role demands transferred across runs. A serial fused producer has only 24.8, 13.4, 8.2 and 7.2 ms of extra scanner demand to spare at the stretch target. The measured local joined computation adds CPU rather than exhibiting the necessary savings. No new complete worker, speculative finder, CI submission or target claim follows.
