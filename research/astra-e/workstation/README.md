# Proposed independent i9 comparison

**Status.** This is a research protocol. The candidate path, candidate source commit, recipe commit, scorer revision, dry-run bundle and CI run IDs must be entered in the Coordinator request before a workstation measurement. No queue entry or ready tag is part of this proposal.

## Population and estimands

Use an i9-10900K with all 20 logical CPUs online and available, unpinned for timings. Decode four concatenated copies of the frozen Wikidata corpus in one stream invocation. The single-copy SHA-256 is `82f65ace0731962d04443bbda4cebfdccd336106049751060f477941c2c29915`. The four-copy SHA-256 is `0b820d14299af637bf7f644d172f5efe91ad59e169cf2a50bd0962f5c89ce08e`, yielding 838,800,784 output bytes. Decode compressed bytes from process memory and drain through the scorer's ordinary worker interface, including RLE1 and CRC, using W workers and 4W slots in every arm. The baseline is v0.5.6's LazyCells, as used by the scorer, in that same calling context. [Earlier i9 sweep](https://github.com/lmmx/mibz2/tree/824d095447faa59d1c33f8e685828784aed863ee/opend-sweep)

Use the scorer's `sweep` on `lazy,opend,open,candidate` at W = 7, 8, 9, 10 in 16 complete rounds, with a 2 s settle between fresh processes. `open` is ungated. Sixteen rounds complete two eight-round forward/reverse ordering cycles for four arms. Wall time and process peak RSS (`VmHWM`) are the primary observations. Each cell pairs runs by round at the same W. Use no hardware-counter wrapper in the timed measurements. Differences in i9 instruction work, IPC, chain latency and IMC traffic require a separate diagnostic run if the observed wall and RSS results justify one.

## Decision rule to post before data

1. Require the full scorer correctness verdict on the candidate, quick control verdicts, the fixed 256-row roster in its scheduled order and correct decoded length every time. A crashed or missing run, nonpositive RSS, wrong length or changed scorer invalidates the measurement. Archive the failure and its cause. A prospective new run gets a new directory and all arms restart together.
2. At each W compute the geometric mean of paired wall ratios and its two-sided 95% t interval on logarithms using the scorer's implementation. Compute that interval separately on the paired process-peak ratios. Report the scorer's ratio of median peaks, both maximum observed peaks, full intervals and all raw samples. The primary ratio is candidate/LazyCells. Candidate/opend and candidate/open use the same rounds as secondary comparisons. Every W is reported.
3. The target-machine criterion passes if **at every W** the upper wall endpoint is ≤0.800, the upper RSS endpoint is ≤1.000, the ratio of median peaks is ≤1.000 and the maximum observed candidate peak is no greater than the maximum observed lazy peak. Passing is the intersection of these prespecified cells and conditions. The rule does not select a best W after timing. The confidence intervals describe sampled per-round ratios, and the maxima cover the observations made in this run. A candidate can earn a smaller milestone against opend when its upper wall endpoint is below one at a specified W and report that W explicitly. The campaign also requires the candidate's exact revision to run on independent CI. An ordinary stock-on-stock green CI check supplies no candidate timing.

## Rehearsal and freeze

Run `bash research/astra-e/workstation/run.sh dry path/to/candidate.rs` on a clean, dedicated checkout of the proposed commit. This builds the locked executable, invokes the full candidate and quick reference correctness gates, checks the corpus digest and writes the planned rotor. It does no timed `run` or `sweep`. On a host with sufficient CPUs it repeats the candidate's quick gate with available parallelism restricted in turn to each W. Those affinity restrictions apply only to these untimed tests. A smaller local machine records the target worker-gate counts it could exercise. Use the actual target dry run to cover the remaining counts. Check all four `gate-candidate-w*.jsonl` files in the i9 dry-run bundle before measuring.

The uploadable archive is under `target/astra-e/`. Compare the preserved diff versus release `530ed404a014a414ef0b62adfd947fa14d4533e6`, including the scorer feature's run accessor, to ensure the measured lazy baseline still runs the 0.5.6 computation. Check the candidate has a research-only entry and that CI ran that entry against its independently built baseline. Record the exact CI head/base, actual arm identities and 1/2/4-thread results. Retain low-concurrency regressions alongside any favourable i9 comparison.

The Coordinator freezes a bare `just` recipe invoking `bash research/astra-e/workstation/run.sh measure <fixed-tracked-candidate-path>` at an immutable commit, publishes the decision rule on #145 and handles queue and readiness after review. The frozen external entry uses `just submit <registered-recipe>`. The research runner stores source revision/tree, scorer info and verbatim report, SHA-256 for the inputs and harness binary, compiler version, topology, complete gate output, all process samples and `decision.json`. After upload, check the returned evidence-branch commit and archive digest. The run decides a research comparison. Changing a production default has its own review and registration. [Workstation instructions](https://github.com/lmmx/mibz2/blob/9c31461df7bef24cecf79348545b27ee26846835/CLAUDE.md)

Tag and data must refer to the same scorer. Both modes fetch master, check for drift and refresh the identical files as required. A scorer update after a proposed freeze calls for rechecking baseline and best candidate together in the research worktree before registering a revised recipe. An incompatible update is recorded and the last working scorer remains available by its tree ID and commit. Any exceptional use for workstation evidence needs an explicit scorer pin in the registration.
