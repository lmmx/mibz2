# Order of complete jobs in a 4W window

Use the eight archived level-2 W4 stock scanner plus frozen scalar-cap timelines on the two-copy corpus. An opportunity begins only after all Huffman symbols and the EOB of a block are known. A single sequential scanner can start block i after it enqueued i−1 and after the reader took i−4W. A free worker selects one complete queued job, executes it nonpreemptively, and returns its ready result. The reader takes in increasing order and copies each output before requesting the next. This tests order only, leaving all service durations and the number of slots fixed.

Before inspecting alternative makespans, compare zero-overhead FIFO, oracle longest service, longest symbol count known when enqueued, and longest among the four oldest available as an anti-starvation control, using the same release and copy rule. Bound every possible nonpreemptive order using worker capacity of all released suffixes of each completed prefix, per-job latency, serial scan, ordered reader and slot feedback. Validate the certified bound and event implementation on small exhaustive schedules, including delaying a cheap early job that frees a slot. Keep local thread CPU shape and recorded elapsed worker service as separate scenarios. Eight timelines supply descriptive robustness, with no interval or performance claim from model outputs.

Extend to W7–10 only as a declared shape transfer. Use genuine scalar CPU and wall receipts, and absolute scanner/main demand transported from the old target occupation sweep. The target scalar has no per-block role trace. Model a symbol-count rule that changes the space of available jobs under actual slot feedback. Require a consistent benefit over FIFO across recorded shapes and a credible scale after calibration before an executable-worker prototype. A priority queue, synchronization, locality and retained per-worker scratch would be paid by such a worker.
