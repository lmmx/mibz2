# Prospective worker comparison

The feature-limited `invert_symbol_runs` hook runs after the normal run-route admission. A successful candidate returns the complete register-compatible inverse in the caller’s usual raw buffer; the library still performs RLE1, block CRC and rollback. Declines use exactly the previous combined and LazyCells paths. The standard decoder build does not include this hook.

Freeze this candidate against narrow-short/ahead at `80d8409359214b4e5abfd4430213921e82e9cd30` using the identical refreshed scorer projection, corpus, allocation policy and worker concurrency. Run each full correctness gate and then independently pair the two complete workers at W1, W2 and W4 (20 or more rotations with two-second settles). Record raw wall, CPU and process peak RSS with Lazy, eager and opend anchors in the same artifact where available. A candidate/predecessor wall interval wholly below 1 at a tested worker count is evidence of improvement there. Report all worker counts and RSS ratios; retain 80d8409 as the target reference pending measurement at the target concurrency. The native 0.968 estimate and routes refer to a weighted CPU diagnostic, not the criterion for changing that reference.

The independent 20-pair CI run on the AMD EPYC 9V45 completed all 300 observations. Against the frozen 80d8409 combined worker the full-worker wall ratios were 1.0110 [0.9946,1.0276], 1.0212 [1.0084,1.0342] and 1.0122 [0.9946,1.0301] at W1/2/4. Median peak RSS ratios were 0.9986, 0.9998 and 1.0208. These results establish a W2 regression and leave the W1/W4 differences unresolved. The candidate remains a reproducible cross-phase implementation, while the measured i9 edge worker retains the performance lead.
