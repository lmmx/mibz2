# Bitmap-precounted direct front

Apply the sparse cap-count formula before the MTF loop. When the cap count times 20 already reaches three times the maximum possible rows, the candidate delegates immediately with empty speculative queues and strips. Otherwise the front emits directly into geometry and final admission uses the exact total. The per-run cap division and running virtual cap counter are gone.

The same SIMD pass takes the maximum literal index seen. Checking it against EOB and checking distinctness of the active inverse-MTF alphabet certifies that nonempty emitted runs have different adjacent bytes. An invalid table, oversized index, or an unsupported EOB delegates to the ordinary front. Values after EOB can cause a conservative delegation when they share its SIMD window, preserving the parsed output. Run widths larger than 127 are checked against the block bound before feeding them to geometry. Short widths are bounded at bitmap transitions and before acceptance. An invalid terminal word can transiently build at most 64 extra maximal widths of at most 127; at most 1,024 speculative thin rows (4,096 bytes of queue entries, excluding possible vector capacity growth) can occur beyond the last length check. The stock replay decides the precise error order. The scalar path remains the stock front.
