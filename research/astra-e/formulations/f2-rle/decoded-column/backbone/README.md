# An exact worker that updates the cyclic BWT and writes decoded bytes

The worker at `d9a6cb24d835864f53d7953f0acee3abd1157de0` implements the [simultaneous predecessor construction](../local-update/README.md). Its source is isolated from the shipping decoder. It locates disjoint count events using the original cap stream, transforms the *sorted last column itself* and inverts the corrected column directly into the caller’s output. It does not construct an original raw output or apply a separate RLE1 pass on the direct path.

**Sparse order representation.** Original rows remain in increasing absolute rank except for explicitly extracted identities. Keep sorted old holes and a vector of exceptional rows, each anchored before an original coordinate. For an explicit position at vector index j and anchor a, the number of corrected rows preceding it equals a minus the number of holes below a plus j. The analogous per-symbol formula uses one old run-rank query, subtracts removed old symbols, and adds preceding explicit symbols. New row identities and their sparse successor/predecessor overrides support exact iteration without an n-entry LF or emitted-text array. In each epoch rank the active rows, retain the longest increasing order within each matching inactive gap, extract the rest simultaneously, and insert them into their prescribed positions. Iterate on precisely the text predecessors of extracted rows. Stream original cap fragments and explicit symbols in their new order to construct corrected run records. A changed predecessor label at the successor of a count gap is explicitly represented.

**Mark and finite length.** Admit isolated five-position cylinders outside the primary. Replacing one count position by k copies leaves each original nonempty Ψ cycle nonempty, because the other four positions survive. Once target and present ranks coincide on the entire active frontier, the corrected column’s stable predecessor relation agrees with the edited identity permutation. Transfer the primary identity to its new rank, construct the ordinary narrow/ahead return map on the corrected capped column, and emit one marked lap. Its output length equals the total corrected row count exactly when the marked cycle contains all corrected rows (equivalently all original rows). Otherwise discard the provisional output and decode the original n marked bytes with the normal RLE1 parser. Repeated or equal rotations need no assertion of uniqueness on the worker path. Nonconvergence falls back under the rank work cap. The caller’s original output prefix stays intact. Limits are 1,024 potential starts, 4,096 inserted bytes, 8,192 active-rank queries, and at most 900,000 corrected rows for the existing inverse. Overlap, a mark inside the window, and other rejected geometries use the same exact original worker. [Source](candidate.rs) · [Sparse order](order.rs) · [Capped output and marked finish](finish.rs)

**Paid costs.** All four native arms ran the inverse, expansion, and stored CRC on the same nine systematic admissions across 32 balanced rounds. Thread CPU ratios were 1.768 [1.210,2.583] versus the combined sparse-word writer, 1.245 [0.732,2.118] versus narrow/ahead and 0.961 [0.634,1.454] versus opend. Wall intervals were also wide. The update kernel's retained vector high water, including its persistent old-run index and the caller’s output, was 10,779,008 B, versus 7,910,380 B opend, 7,558,316 B narrow/ahead and 6,730,182 B the sparse-word writer. The per-epoch overlay, character directories, sorting scratch, hash tables and outstanding edit records are temporary additional live memory, outside those retained figures. The work cap bounds their size by O(h+k+Q) words for h counts, k inserted positions and Q active-rank queries. No process RSS, cache, instruction, CI or target-machine claim is made for this constructor. [All 1,152 timed observations](phases.csv) · [Summaries](summary.txt)

A separate 24-round alternating phase build recorded median nine-block CPU sums of 5.947 ms building original navigation, 0.418 ms finding count events, 7.630 ms updating ranks and 4.628 ms scattering corrected caps. Corrected return-map construction took 18.587 ms and one-lap copying 12.853 ms. The original narrow/ahead arm used 1.232 ms for stock RLE1 over the same blocks. Its complete phase median was 34.441 ms, versus 54.107 ms corrected-column. Even with free ordering, the two full input/output cap scans alone cost 8.58 times the eliminated parser in this build. The mathematical gain from batching is real; the measured cost restricts its application to this throughput objective. [Phase observations](attribution.csv) · [Phase totals](attribution-summary.txt)

**Continuation.** A paid candidate would need to eliminate the full original index build *and* the corrected-column materialization, or derive a cheaper inverse from the changed geometry. First test whether the existing constructor’s run splitting can supply exact rank/navigation for the sparse frontier while its adjusted original cap intervals flow directly into corrected return construction. Charge the extra scan, any repeated split/queue construction, all residual creation, and fallback memory. The earlier combined writer remains the comparison for direct output; building another faster sorting routine alone cannot pay for the two measured scans. The standalone corrected-BWT transform also retains independent value for applications that actually require an ordered compressed column.
