# Unselected successors can share their source alias

Fix any side assignment with the protected singleton outside. For each old outside source class k, scan its occupied destination classes in destination order. Give each selected destination j its own (k,j) alias as before. Between them, make one alias for all consecutive occupied **outside** destinations. Empty intervening destination buckets contribute nothing. An inside source class remains a single alias. Each such block is still contiguous in the source order because π is increasing on all of k. A selected alias has exactly the target and weight of the original refinement. A gap alias keeps W_k and skips no vertex. Its map through the surviving destination subsequence is the restriction of the old increasing π; no restriction about its successor classes being equal is necessary. Thus the same outside→inside mass is removed, the marked source survives, and every stable partner and spelling remains exact. Later cuts may change because coarsening changes the source alphabet.

On an outside source class with h occupied target classes inside T, the alias count is h plus the number of occupied outside gaps. The latter is at most h+1. When h=0, the whole old class needs one alias. New class boundaries on the incoming side remain a subset of the old H run/bucket slices. This is the coarsest refinement of an old source class which retains each selected target separately and uses only consecutive source intervals while merging every permissible unselected neighbor. Selected neighbors can have different payloads or reordered second destinations and require a separate condition to merge.
