# Two ranked sections form a single stable weighted token column

A second induction can keep the dominant **core** unsplit. Use two ordered copies of the ranks, first all m physical cut ordinals V and then all m original delimiter ordinals U. A V token emits its core C and moves to the original return destination D(v) in U. A U token emits its own prefix P(s) and moves to its cut g(s) in V. Two successive transitions on this 2m-row column implement the physical permutation Φ = g ∘ D. The constructor consumes the original incoming core RLE, core counts and bucket order, and the forward prefix atlas; it needs neither follower-pair labels nor old full-word types. The existing Rust second stage decoded all 60 real marked blocks with this interface, both with its usual choice of delimiter and with the dominant core forced. ## Constructing the alphabet and the incoming column

In the V source half, give each positive core C a single token ID, in its physical source-bucket order. Its occurrences at old destinations are exactly the supplied incoming core column in U order. Within each C, the j-th physical V source maps to the j-th incoming occurrence in U. This follows from stable Ψ along that fixed positive core and full-interval collation for the landing section. [Full physical interval proof](../audit/README.md)

In the U source half, group each **maximal contiguous run of the same literal prefix** P in original U source order under one fresh prefix ID. Assign all prefix IDs after the core IDs. This grouping may give the same literal multiple IDs when it recurs after other prefixes. Their byte payloads can alias the same slice. For fixed P, g(s) = Ψ to the power |P| at s, which strictly preserves order on the cylinder P. Thus the j-th U source of this prefix ID maps to its j-th incoming copy in V. For P empty, the map remains the identity on original physical ranks and the phase changes with zero emitted bytes. Repeated infinite byte itineraries do not identify ranked rows.

Place the incoming prefix IDs in physical V order by reading the atlas bands in that order. Append the incoming core RLE in U order. Stable occurrence ranks on this single last column now give the inverse transitions in each phase. Its exact maximal run count is R_prefix + R_core. The alphabets on opposite sides are disjoint, so the centre seam cannot merge. R_prefix ≤ B for B physical atlas bands. Constructing the prefix IDs takes one source-order traversal of the atlas and publishing the incoming prefix column takes one physical-order traversal. If only one order is available, the other permutation must be built or sorted. This first-level object holds O(K_core + K_prefix + R_core + R_prefix) records plus distinct payload bytes. The stock rank directory spans 2m token positions. Every route still pays the preceding atlas, core discovery and scatter costs.

Ignoring the phase change and putting core IDs straight into a physical V token column fails already for L = [1,0,0], U = [1,3), h = 1. The two cuts are at original ranks 0 and 1. Both emit core [0]. One old prefix emits [1] and the other is empty. Their physical successor swaps the cut ranks; stable occurrence ranks on a one-symbol column give two fixed points. The core-only stable column works exactly when g preserves destination order separately on every core fiber. Recording this extra routing layer supplies the missing information. ## Forcing the anchor without changing the stock writer

Let f be the largest core mass, resolving ties by smallest source base. A prefix ID of mass p greater than f would displace that core as the stock stage's largest token. Subdivide each such prefix's U source bucket into consecutive aliases of width f or less, preserving their spelling and order. Stable occurrence counts split the existing incoming prefix occurrences into the same aliases while scanning in physical V order. Each added source boundary splits at most one physical incoming run. Every remaining prefix has mass at most f. All cores precede all prefixes in source order, so the existing first-column tie rule selects the desired core.

At fixed core masses and source order this uses the smallest possible number of additional prefix IDs, the sum over old prefix IDs of ceil(p/f)−1. Each old bucket needs at least ceil(p/f) IDs if their masses are capped by f. The cap can change second-level symbolic dictionaries by distinguishing aliases with equal emitted bytes. An unforced prefix anchor is itself valid and may suit a different marked cycle or cost less. [Minimal-alias adapter](lift.py) · [Explicit stock tie rule](../../../../../../f2c/second.rs)

## Inducing the dominant core and writing the mark

The dominant core has one interval H in the V half of the lifted order. Starting at the leftmost uncovered H destination, apply the single column's inverse until its first positive return to H. At each step clip the candidate width to the end of the current incoming run, then clip at the nearest H boundary after translation. Record the token IDs in reverse order. The entire width follows that same path, so its source and destination translate by a constant and its forward weights give the exact physical bytes. Continue at the next uncovered H destination. The sparse writer stores source-sorted bands and shares complete token-ID sequences in a dictionary. The native stock writer instead materializes the second dictionary bytes and a packed link per H source.

The representative paths of distinct H destinations lie on disjoint inter-visit arcs, one for each chosen destination. Thus the direct constructor makes at most 2m inverse token lookups, or m core/prefix pairs. If the lifted column has R maximal runs, at most R+2 returned bands can arise. For adjacent H destinations trace the left ranks until their first split. The event must be an incoming run seam or one of the two H-membership seams after translation. A given incoming seam corresponds to one left rank. Each landing seam also has a unique predecessor left rank under the permutation. Distinct destination paths have disjoint left-rank histories up to return, so each seam accounts for at most one splitting pair. These are upper bounds for lookup count and fragmentation; each lookup still needs rank support. A chosen anchor can have a long route even when H itself is small.

The marked rank can start inside a prefix or a core. Rewind original LF to the nearest preceding U-source or V-cut boundary and retain the number of original bytes skipped. At a coincident boundary the U prefix is empty; choose the V row to give the first outgoing byte a positive token. Every lifted cycle alternates phases, with a positive core every two transitions. Thus an empty prefix cannot create a zero-output cycle. A marked lifted cycle missing H can follow its original lifted links until n bytes; the stock adapter uses its direct fallback there. If the original marked cycle misses U entirely, the experiment uses the original run-based Ψ and emits n bytes. Every completion uses n original bytes, including a truncated final lap.
