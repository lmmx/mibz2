# A physical ordinal alphabet can reuse the existing second writer

The native second induction accepts an incoming maximal run stream over any ordinal alphabet with stable source buckets. Different IDs may emit identical bytes, including through the same dictionary slice. The numeric IDs and the lexicographic order of their bytes may both disagree with source-bucket order. The existing native `consume(Object)` adapter takes the root runs, word byte ranges, source bases, byte dictionary, marked source row, byte skip, occurrence count m, and output length n. [Adapter](../../../../seams/async/native/token-writer/interface.rs) · [Second induction, unchanged since 3156570](../../../../../../f2c/second.rs)

For each ID i, its positive count cᵢ equals the sum of its destination run widths. Its source interval [bᵢ,bᵢ+cᵢ) is disjoint from the others and all intervals partition [0,m). The j-th occurrence of i in destination order must come from source bᵢ+j. Then `Second::column` constructs precisely this LF by recording bᵢ plus the earlier occurrence count at each run start. All discovery comparisons, child epochs and delimiter selection use integer IDs. Byte spellings enter only when accumulating byte offsets and copying a completed second word. The dictionary slice for each ID must have positive width and spell its complete physical arc. For an arc from one cut terminal to the next, those bytes are its current core followed by the prefix belonging to the next original source. The primary is an ordinal in the cut section plus a skip within that source's outgoing spelling. Adjacent aliases retain their distinct IDs and bases whenever joining them would change this stable map.

On the successful path the first column occupies one token record per incoming run plus page masks and bases. The second stage also allocates a residual link per occurrence of its most frequent ID, which can approach m. All-one-ID columns, marked cycles missing that ID, and a second packed-link overflow return false. The current adapter then builds m direct links. A strict requirement to avoid that fallback allocation needs a separate fallback or explicit admission. One sparse fallback can group the first runs by ID with cumulative counts and destination starts. For a source x in ID i, select local occurrence x−bᵢ in those cumulative counts, emit i's bytes, and jump to the selected destination. This needs O(K+R) stored records, per-emitted-token predecessor work and the original cycle/tail truncation. Marked cycles missing the first section still need the original byte fallback.

The existing library accepted 6,998 cases through the second stage and handled 1,164 through its fallback across 852 small ordinal columns. Numeric source order was deliberately reversed. In 5,898 native second-stage cases, two IDs shared the same physical byte slice and a third emitted different bytes. All 8,162 marked streams agreed with an independent stable-Ψ walk, including every valid intra-word skip and 4,820 byte lengths ending mid-lap on a shorter marked cycle.
