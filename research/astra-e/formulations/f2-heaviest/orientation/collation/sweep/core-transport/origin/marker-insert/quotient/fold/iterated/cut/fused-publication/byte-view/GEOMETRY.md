# A bounded first-step join directory

For the initial original-byte cut the number K of nonempty seeded source classes is at most 258. A dense K×K u32 table charged on the first step can serve both the cut chooser and the publisher. Initially entry [u,j] records the exact mass of old incoming seeded u in destination bucket j. A traversal of original caps cut only at z and at destination bucket boundaries fills the table and saves a cap index/intra-cap offset at each old bucket start. The chooser's signed conditional vote is the sum of each previously colored class's mass in row k and in column k with the corresponding sign. The prescribed protected class is decided first. Computing all colors costs O(K²). A separate pass supplies all deleted target masses. In old source order, replace each positive outside entry [u,j] by its final ordinal ID and create precisely the corresponding old or joined handle. The matrix now serves every outer and secondary query in constant time. Selected target classes need at most one ID each. This replaces both an old H-sized slice buffer and secondary searches; the dense directory costs 4K² bytes and must be priced. At K=258 its payload is 266,256 bytes, as distinct from the approximately 10 KiB mask-only design that would still need a separate source of weighted votes. A single linear weighted directory avoids paying for both representations.

For R original capped records, at most R+K+1 initial joint pieces (one physical marked cap split adds up to two boundaries; K buckets add K−1). Each old target stream in publication has its own cursor at the correct global source bucket start. The old physical cap containing z is the only cap whose label depends on a local offset inside that cap. With unchanged full reconstruction as fallback when the first quarter-cut is ineligible, all route recognition and any redundant materialization remain charged. On a successful cut the leading construction uses O(R+K²+new output runs) work and O(K²+K) auxiliary storage beyond outgoing grammar and RLE. Neither the maximal-run column, nor the seeded old column, nor an H-sized old coordinate table is needed.
