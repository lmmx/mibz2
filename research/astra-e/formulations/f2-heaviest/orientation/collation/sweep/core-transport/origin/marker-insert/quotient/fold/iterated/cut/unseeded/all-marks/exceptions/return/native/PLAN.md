# Paid construction of the ordered clock

Both arms receive the same original cap-127 records, physical primary and sorted true-exception ranges. Produce (backward time, sorted-exception ordinal) for every exceptional visit during one exact original marked lap and return its length. The ordinal indexes a future restart-state or spelling table. Obtaining the physical ranges and that table from the original column is uncharged in both arms. Output bytes, RLE1 and CRC belong to later stages.

The control constructs a dense stable LF in two capped-record passes. Use its spare high bits for one local exception ordinal per row and a small 256-row prefix directory. Ordinary rows need one LF load. The treatment constructs the source-run/return-membership overlay, processes source-order packets with a 256-row predecessor directory, writes the induced successor and distance directly into one 8-byte entry per U row, and chases those entries from the mark. Reuse each arm's scratch and output across all ten blocks. Count every real cap, directory, span, packet, dense return and event. Check every returned clock pair before and after pricing against independent direct LF and the pinned predictor wires.

For each of k=4,8,16 run 24 matched whole ten-block laps, alternating AB/BA in each k, with k order rotated by round. Use a single pinned core and CLOCK_THREAD_CPUTIME_ID separately for each block call. Retain all block observations and two-sided paired log-t intervals over complete laps per k. Separately record fresh-process pre/post VmHWM and vector capacities for each block/arm. Both the strong direct control and the induced constructor return clocks only. No inference about i9 throughput or complete scalar memory follows from this panel.
