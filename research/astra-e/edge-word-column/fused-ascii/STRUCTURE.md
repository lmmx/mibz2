# Direct queued shortcuts

For a band starting at physical rank d and queue ordinal k, its old target is y = Q[k+x−d]. In a physical partner band [e,f) the next target is Q[l+y−e]. A directory of old physical bands suffices to select the second queue. Coalesce adjacent qualifying bands when the ASCII byte and queue offset delta agree; coalesce all consecutive nonqualifying partners as one range. The old Q slice is strictly increasing within the source band, so one partner lookup suffices for every group until Q crosses its upper boundary. No old dense successor feeds the new output. The retained array still has one four-byte entry per old rank.

An active shortcut at x emits exactly the two old ASCII literals and advances two original arcs. Forbid it when y is the mark, so it cannot jump across a marked lap ending. Simultaneously enabling overlapping starts is valid since each decision reads only the original unmodified queues. Traversal from the mark always advances positively within one old lap, visits the mark again after the same byte spelling, and repeats or truncates exactly to the block length, even on a short marked cycle. An unmarked two-cycle can become two self loops without changing the required marked bytes. Standard dictionary entries lie strictly below the first pair code. Blocks that cannot fit the complete 14-bit pair alphabet retain the original codec and mark behavior.

Among all 233 edge admissions, 187 fit this frozen packing policy. On these 18,658,864 rows the directory represents 647,045 physical bands, or 254,003 merged partner ranges. From 15,160,851 ASCII source positions the constructor walks 1,769,715 range claims, of which 1,611,822 qualify as ASCII pairs, and gathers 13,429,533 second targets from the original immutable queues. The old dense postpass ran 15,160,694 indexed entry tests and rewrote 8,909,398 entries. Its 12,530,137 remaining marked hops fall to 11,573,452 for the direct simultaneous version. Across all 233 the stock, old postpass and fused hop counts are 26,567,581, 20,438,854 and 19,482,169. On the frozen first block these are 89,874, 59,511 and 54,456. The lookup and gather streams have different locality. In particular the new builder must construct and query its directory, perform extra second-Q gathers and handle a second output tag. Hops alone cannot price it. [Per-block counts](fused-pairs.csv) · [All-row reference comparison](fused-pairs-check.txt) · [Exact census](census.cpp)

The marked hop count is optimal for this exact fixed two-ASCII packing rule at the elementary decoding level. Linearize one old marked lap at its required starting vertex, with no pair spanning the terminal return. Every maximal consecutive ASCII run of length l permits at most floor(l/2) disjoint two-byte substitutions. The simultaneous table takes the earliest available pair on the actual walk, pairs successively through that run, and realizes exactly floor(l/2). Treat ASCII runs broken by the primary boundary separately. Thus a different pair coloring or physical scan order cannot improve the 19,482,169 corpus hop count while keeping this fixed alphabet, packing guard, at most two old steps per new hop and the original mark convention. A lower construction cost remains a distinct possibility.
