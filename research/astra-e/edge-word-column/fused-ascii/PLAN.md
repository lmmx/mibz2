# Compose ASCII literal pairs directly from the original queues

The old postpass at 28ae0cf read and modified an already dense successor and gained no independent speed result. A different construction can publish the shortcut while filling the successor once. Keep the existing eligible 14-bit ASCII pair format and block packing predicate. For each original literal ASCII band use its ascending Q slice, splitting at physical partner-band boundaries only when Q crosses such a boundary. A nonliteral partner band remains ordinary. If the partner is also literal ASCII and is not the original mark, compose its actual second target by a select in the existing queue for that band. Use all eligible starts, including adjacent starts, since our reads are from immutable old Q. The participating interior row need not be deleted. Preserve every old rank and block mark and add no per-row old successor buffer. Compare total and *marked* shortcuts to the old in-place order, range counts, random/select reads to find spans, mandatory second-Q gathers, fixed-code availability and primary exclusion. Count table and mark visits. Verify against every old table, all coded bytes and finite arbitrary marked permutations. Decide from paid construction and full native output before calling it a performance candidate. This experiment can only change work on eligible blocks. It is distinct from assuming a graph-free quarter cut is cheap.
