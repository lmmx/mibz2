## Common information before publication

For each old source class I let S(I) be its fixed cut color. Protect the old primary by giving it its own outside singleton. The preceding certificate partitions every old physical band into consecutive source intervals labelled (I,J,w), where J is the class containing its destination. Its old targets are an increasing contiguous *slice of a byte queue* even when there are physical gaps between the targets. The previous method used a band-start bitmap. This implementation sorts B band starts, stores K seeded class boundaries, and binary-searches that sparse vector for target classes. It uses no m-bit rank array. Across 233 inputs this takes 2,568,304 certificate fragments, 11,692,513 Q reads and 36,866,725 comparisons with class boundaries (including the source queries). Sorting the band list and recognizing equal byte spellings are additional costs. [Prior exact certificate](../README.md) · [Full count cross-check](counts.txt)

The color and these pair masses determine every output source alias. An outside source gets a distinct joined alias for each occupied inside destination, and one unchanged alias per intervening gap of occupied outside destinations. Their order follows old source rank because destinations increase on that source class. Every outside source survives. Inside source I has exactly width(I) minus its entering outside mass surviving, giving one alias I′ if positive. These counts assign alias ordinal IDs and the new marked source before arrival order is known.

Consider the old edge z→x. At old destination x in an inside class J, the tag for J’s subsequent outgoing edge is A(source(z),J) when z is outside, or J′ when z is inside. Call this the ancestry tag at x. A fully deleted J can have many such joined tags but never needs its absent surviving ID. At an outside x, the tag for the outgoing edge x→p is Skip when p is inside and A(source(x),source(p)) otherwise. In physical old destination order, emit the resulting tag of its predecessor, omitting Skip, and coalesce adjacent equal IDs. This gives precisely stable survivor order and the old two-hop contraction. Since deleted rows are inside with an outside predecessor, two successive deleted rows are impossible. The protected mark is outside and survives; unrelated cycles are not merged and the marked horizon can end partway through a repeated old lap.

## Two direct iterators

**Suspended ancestry.** For each byte c the existing Q list is sorted by original physical destination. Its intersection with each old destination bucket J is one slice. The certificate in old Q order supplies the positions, widths and ancestry tags of that slice. Coalesce outer queue directives into Skip, fixed alias ID or Pull(I). Inside I needs a pull only when it has multiple distinct ancestry tags. At each resumed occurrence the predecessor x takes the next rank of the contiguous source interval I, in strict order even across old band boundaries. Weave its (I,c) tag streams by physical byte order, emitting as many identical current tags as the suspended outer directive requests. Each real or synthetic queue merge in the test uses its actual sorted Q slices: after the minimum rank p wins, the next smallest competitor at s proves this byte covers all positions in [p,s). Pop one item, advance by s−p, then reinsert the new head if needed. This gives exact order without emitting the old high-ID column. Source-bucket cursors cover disjoint physical regions. As an alternative, the original capped input can provide physical low-byte order by a forward retained-run iterator and one registered cursor per mixed bucket. Its actual low-byte/cap recognition work needs to be charged.

There are 1,105,287 outer directives and 1,100,057 stored ancestry runs in 986,265 occupied (mixed bucket,byte) bins. The outer pass takes 14,371,619 claims and the inner 8,119,413. Inside buckets with constant ancestry cover 494,795 rows, while 12,822,401 require mixed ancestry. The pure Q merge uses 14,291,364 outer and 7,089,895 inner low-byte runs and Q-head reads, and **144,082,250 outer plus 42,988,593 inner heap comparisons**. These figures include heap initialization and repeated pop/push. Access to a cheap existing low-byte iterator can remove heap work, but it still must align the resulting physical order with tag changes. [Measured per-block charges](observations.csv)

**Source-order annotation.** Scan old x in physical source-band order. For an outside source the outgoing certificate supplies its fixed or skipped tag directly. For an inside source the input ancestry at x instead supplies the final tag. Compute ancestry in one old low-byte scan with 256 Q-ordered tag cursors. Append the resulting tag and width to x’s own physical band. Within the band, x→T(x) is the corresponding interval of the old queue with the same offset. Read the band lists back in old queue order; on a second physical low-byte scan consume tags for each byte, emit surviving tags and coalesce. This avoids all suspended per-bucket readers and allocates only runs of already-final tags or Skip. The first pass visits 14,549,428 composition claims and stores 6,596,764 per-band tags (6,429,520 after queue coalescing). The replay visits 15,195,974 claims. Each complete low-order pass has the same 14,291,364 low-byte runs and 144,082,250 heap comparisons if generated from Q. Both schedules produce exactly **11,342,758 output RLE records**, representing 19,725,442 survivors and 1,155,219 alias classes. These are structural counts, with no new CPU, peak RSS or target projection.

The earlier fused publication at 7b7c9c94 reads an actual old high-ID incoming RLE and resumes one cursor directly in each selected source bucket. The edge formulation starts with Q and physical bands instead. Suspended reading requires old byte-order recovery and sparse (bucket,byte) cursors. Conversely the explicit source schedule above pays to stage tag runs before decoding physical destination order. Neither removes the need for order within the destination bucket. The old four-row witness is already nontrivial under a cut: for F=0122, primary zero and inside class 1, old incoming 1202 and 1220 have identical class-pair masses. After contraction both have the same ordinal weights (0, 21, 2), but their true incoming columns become 102 and 120, respectively. ## Verification and replay

The direct algorithms share only certificate/source information with their reference. The verifier separately derives the old incoming from the frozen dense truth, invokes the earlier gap publisher on that RLE, checks each output alias and RLE record, decodes the resulting stable permutation and verifies the whole marked byte stream. Exhaustive additional tests covered **26,042 marked weighted/color assignments**, including 20,920 shorter marked laps and 16,476 nondivisor horizons. They include all binary old columns through six rows and ternary old columns through five, every physical primary and every color bitmask after protecting the singleton. Some assignments coincide after forcing the primary outside. [Finite checks](small.txt) · [All real marked checks](checked.txt)

After running the parent edge-word-column replay to materialize the thin tape, reproduce from the repository root. The edge and word tapes may also be supplied from their original checked capture instead of the replay directory. No benchmark run is requested by the structural result.

```bash
d=research/astra-e/edge-word-column/certificate/ordered
t=/tmp/astra-edge-ordinary-replay
g++ -std=c++20 -O2 -Wall -Wextra "$d/ordered.cpp" "$d/stock.cpp" -o "$t/ordered"
"$t/ordered" small | cmp "$d/small.txt" -
"$t/ordered" "$t/edges.bin" "$t/words.bin" "$t/thin.bin" > "$t/ordered.csv" 2>"$t/ordered-check.txt"
cmp "$d/observations.csv" "$t/ordered.csv"
cmp "$d/checked.txt" "$t/ordered-check.txt"
python3 "$d/verify.py" | cmp "$d/counts.txt" -
```
