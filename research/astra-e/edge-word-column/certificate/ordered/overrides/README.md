# Publish by skipping a known modal ancestry

The direct publishers at 9e45d8cd already supply true survivor order. Their pure-Q reconstruction of low-byte order uses 187.07 million outer and inner heap comparisons (144,082,250 plus 42,988,593). This follow-up instead reads actual original capped L records for the outer destination stream, with the incumbent’s width-16 retained rule and primary singleton. It also reduces the inner problem from recovering all of a bucket’s incoming order to recovering only its nondefault exceptions. The output still matches every stock gap-publisher alias and ordered run, on all 233 admissions and 26,042 tiny marked/color assignments. [Measured transition and cap counts](observations.csv) · [Verified reduction](counts.txt)

On a mixed inside target bucket J, every ancestral joined alias A(u,J) has width equal to its incoming mass in J; that alias applies to exactly those outside u rows whose successor lands in J. Its other possible tag, the surviving carry J′, has width equal to the number of inside predecessors in J. Thus the most frequent tag can be chosen directly from already assigned positive alias widths, breaking ties by smallest ID. Every rank of J which does not belong to a different tag emits this mode. The occupied (J,c) streams of the original certificate give contiguous Q slices for each nondefault ancestry tag; zero-width intervals are absent.

For each mixed J, take only these exceptional slices of the old original queues. Read their physical positions, advancing an individual queue in order. A heap over the active byte heads provides physical order across bytes. When adjacent physical positions of the same input slice can already be seen in a queue, emit one interval for the entire consecutive extent; no other queue can intervene in it. Coalesce adjacent same-tag intervals after merging. The complementary physical positions have the mode by construction. As the outer physical capped iteration requests Pull(J), its ancestor advances through the J source interval. Compare this position to the next exceptional interval, emitting the mode over gaps and the exceptional tag inside each interval. The outer scan otherwise emits its fixed alias or skips a deleted destination. Neither an old high-ID incoming tape nor an ordinal-indexed deletion table is needed. Across all 233 admissions the modal stream covers 6,320,186 nondefault rows (49.29% of the mixed source positions) via 589,980 exceptional queue slices in 538,404 occupied bins. Exactly 6,320,186 Q values are loaded, one per exceptional row. The heaps make 18,477,009 comparisons and produce 3,646,343 physically contiguous tagged fragments, merged to 3,631,413 exceptional intervals. The global capped output pass consumes all 16,320,934 original cap records, recognizing 15,141,602 maximal original L runs and 14,386,594 raw retained pieces. This differs from the 14,291,364 maximal *retained* low-byte runs because the cap reader retains the boundaries across discarded original runs. It visits 14,448,215 outer directives/chunks and 7,916,591 mixed ancestry chunks, of which 3,798,904 emit the default from a gap. The 11,692,513 Q reads and 36,866,725 binary class-boundary comparisons to build the shared certificate are additional. The original queue construction, band ordering, recognition of old equal words, scoring and canonical alias assignment also remain chargeable. A single original-cap scan replaces the large outer heap; the previous pure-Q comparison does not charge this scan.

A second independently checked version stages complete ancestry **only** for rows whose outer directive requires Pull(J), using a first original-cap scan. The counts are 5,574,844 runs if kept per original outgoing band, 5,519,907 if coalesced in original outgoing queue order, or 5,505,982 if kept per mixed source J, since Pull(J) already follows source order. It then takes a second capped scan, with 7,916,591 mixed chunks as above. The eager modal triple representation would spend 43,576,956 bytes for (position,end,tag), while the explicitly staged per-J full runs take 44,047,856 bytes at eight bytes per (tag,width). This 470,900-byte aggregate difference excludes all directories, heap nodes, allocations and the final output RLE. It gives no material process-memory or speed advantage. These uncompressed formats price the *staging* choice; an online iterator can instead keep a suspended heap and current exception for each queried J.
