# Packed lookup invariants

A 10-bit prefix identifies zero or more complete canonical codes. Position p ranges from zero through ten. Starting with p=0, inspect the first code at `(prefix << p) & 1023`. The unused bits are padded with zeros. If its reported first length L is nonzero and p+L≤10, all L bits came from the original prefix. The actual next symbol is therefore the same as an individual stock lookup, independent of the padding. Repeating gives the unique ordered code prefix. Stop before an unrepresented ID or a code extending beyond bit 10, and immediately after EOB. A failed later code remains for the next iteration and retains the first bad code’s position.

A successful entry stores total length in bits 0–3 (1–10), first length in 4–7, count minus one in 8–9, EOB-last in bit 10, and its first nine-bit symbol in 11–19. A two-symbol entry uses bits 20–28 for its second full ID. A triple uses six bits each at 20 and 26; a quadruple uses four bits each at 20, 24 and 28. The total entry is four bytes at every arity. A zero low nibble denotes an exception, either the original zero long-code sentinel or original `1<<31` invalid-code sentinel. Valid packed payloads may use bit 31 and remain distinguishable by their nonzero total length. Every LUT entry retains its original first ID and first length throughout construction, so updating earlier rows in place cannot change later first-code reads. The stock canonical-code limits, base, permutation and error predicates are shared verbatim. Each candidate builds its own 1,024-entry LUT per used group.

Let j be the number of symbols selected in the current group. The code takes an entry up to K symbols only while 50−j≥K. Four unrolled body steps need 50−j≥4K; after a stock refill supplying at least 56 bits, even four full ten-bit entries leave at least 16 bits. A long code uses the original slow decoder and refills before the next step. When fewer than K symbols remain the treatment calls the exact first-code decoder successively. EOB is never internal to an entry, and the constructor marks the terminal bit exactly when a phrase ends there. Each step consumes precisely the sum of the original code lengths. The symbol positions and ordered selector changes follow stock by induction. The scanner checks overrun at the same logical group boundaries and the normal stream code handles invalid, truncated, EOB and concatenated members. Speculative storage for a short phrase fits the already-reserved stock `MAX_SYMS` bound because the group has K available positions wherever the treatment emits a phrase. The emitted Vec length advances by the actual arity. Standalone immutable scanner fixtures use no worker implementation.

The all-corpus structural census compares all emitted symbols including EOB. The group tail in this specific design uses the first-code-only path when fewer than K positions remain. Under that policy the unconstrained-ID row is the attainable four-symbol lookup count. It does not minimize all possible selector-tail or direct-table implementations. Greedy grouping minimizes the number of steps for a suffix-closed set of allowed phrases at a fixed group without varying tail policy: consuming a longer first phrase covers at least as many symbols, and the leftover suffix of the displaced shorter step remains feasible. No such optimality claim is needed for the measured census, which follows each implementation's exact policy.

For real-bit references, the original register-resident scanner compared each 10-bit pair path, cold long codes and ending cursor with libbzip2-style lookup on 4,000 generated blocks. The independent check here gives the same generated block, bit offset and cutoff directly to the historical and both new item readers, and compares every reported symbol, block field, error, consumed bit position and overrun flag. Whole-stream testing separately checks normal headers, stored combined CRC verification and concatenated members. The post-Huffman worker and its block CRC are outside the measured scanner stage.
