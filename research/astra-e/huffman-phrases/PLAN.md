# Ten-bit Huffman lookup emitting up to four symbols

Freeze the stock scanner from the 0.5.6 baseline commit `530ed404a014a414ef0b62adfd947fa14d4533e6`. It constructs a 4,096-byte table for each selected Huffman alphabet, represents every legal direct first code and fitting pair, and makes four serial lookups between refills. A lookup can consume at most ten bits no matter how many codes fit. Stock fallback decodes long and invalid codes, groups switch every 50 emitted symbols, and EOB ends immediately.

Count exact greedy invocations on all 431 real blocks, including refilled body, suffix, final EOB and one-symbol selector tail. Count table slots independently of lookup frequencies. Freeze the simple primary four-byte entry with a 4-bit total length, 4-bit first length, 2-bit count-minus-one, 1-bit terminal marker and 21 payload bits. The first ID has 9 bits in every form. Singles and pairs retain full 9-bit IDs. In a triple the next two IDs get 6 bits each; in a quadruple the next three get 4 bits each. A secondary balance bounds all triple IDs to 7 bits and all quadruple IDs to 5, requiring count-dependent first-symbol extraction. Price pairs-only, triples-only, triples-plus-quadruples, and unrestricted ID-width structural ceiling. Changes in table traversal count are diagnostic.

For a working native candidate, compare separately instantiated stock and treatment scanners on the full canonical input in balanced rotations (at least 24). Charge stream and block headers, selection and table construction, refill and slow paths, output symbol storage with stock capacity/reuse, EOB and stream checks. Verify every emitted symbol, block metadata, consumed bits and errors against stock before timing. Include the stock malformed-code differential tests or an equivalently strict independently generated suite. Whole-worker effects require an independent integrated comparison.
