# Frozen near-threshold whole-strip exchange

Reference badb2aec3624bd65606c429b2e6f79e9d9d0050f is the i9-measured bounded writer. It coalesces capped records into true runs, retains runs of at most 16 rows, and retains the primary inside a longer run by splitting around it. The original Open investigation measured queued endpoint widths 8/16/24/32, among other methods. This experiment fixes the threshold and changes strip identities. [Existing width receipts](../../../docs/journal/2026-11-18-open-return/evidence/widths.csv) · [Admission and primary handling](../edge-budget/README.md)

**Pareto limitation.** Freeze the primary's entire run. Among any k other true maximal runs, omitting the k longest maximizes omitted rows. The width rule chooses exactly those longest runs for its k, including all ties at the retained boundary. Every nontrivial identity exchange at fixed k must therefore increase the retained table length. Conversely, at no larger logical table length and no greater omitted true-run count, this rule admits no improving swap. Extra table rows and the reachability/cost of actual endpoint joins must be reported separately.

**Equal intervention budgets.** Exchange q true length-16 and q true length-17 runs, excluding the primary's run. All competing interventions therefore have exactly the same omitted run count and retained width m+q, one extra row per pair. Set q to min(128, available counts on both sides). Reduce q if it changes the successor bit width or if an already guarded block would exceed the original 1 MiB width certificate. Thus the candidate spends at most 128 extra rows (at most 512 bytes for four-byte links), holds the strip count fixed, and preserves reference admission. Larger vector capacity from rounding must be measured. The unmodified width-16 reference remains the speed control.

**Frozen split and policies.** Train only on large canonical Wikidata blocks in streams 0, 3, 6, 9. Hold out streams 1, 2, 4, 5, 7, 8, 10, 11. All table counters on these streams remain blinded until the training winner and decision are written. In each policy a single scan over coalesced records identifies only 16/17 candidates. Neutral exchanges first q of each length. Adjacency omits length-16 candidates with most existing omitted neighbors and retains length-17 candidates with fewest. Count omitted neighbors on each side in source order and on each side in the same-byte LF image order, using the fact that stable LF orders a byte's source runs by original position. Antiadjacency reverses the ranking. Bucket ranks candidates by the fraction of their byte's rows already belonging to omitted true runs (eight equal-width fraction bins), omitting high and retaining low. Identical score ties are decided by original order. The marked run itself is never exchanged; its use as a neighbor may be approximated while choosing identities.

**Training decision.** Price no surrogate sum. Record actual endpoint node count, elimination steps, rules, bands, dictionary bytes, word/edge visits, retained row count and peak selector/table capacities. Choose the nonneutral policy with the smallest summed actual elimination-step ratio against the equal-budget neutral arm. It proceeds to a complete paid held-out native timing screen if it removes at least 1% of those steps, with traced dictionary bytes no more than 1% higher and a step win in at least three of four training streams. If none qualifies, freeze the winner anyway, report its held-out structural consequence and separately charge a complete preclassification against the unchanged decoder before proposing any further worker timing. A rank/operation count never establishes a time win. A useful paid result must beat the original complete control, including classification and changed table costs. Raw structural and timing results will remain separate. CPU-heavy work is serialized away from the ongoing worker-dose benchmark.
