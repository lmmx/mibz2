# Narrow node IDs during open endpoint induction

This candidate reproduces width-16 density-gated Open-Return. In its endpoint constructor `prev` and `next` each contain two node IDs. Moving the four IDs from `u32` to `u16` changes a node from 24 bytes to 16. The four vectors of node IDs used to construct the linked lists also shrink. Widths, word IDs, spelling lengths, strip indices, residual rows and output coordinates retain their original widths. All setup and output operations remain inside the measured worker.

Let H count the wide strips after isolating the primary. Induction allocates one sentinel, H strip nodes, and at most H+1 positive gap nodes in each of two orders. Adjacent gaps with zero width allocate nothing. `cut` and `insert` relink existing nodes, and word concatenation allocates separate word rules. Thus the total number of node slots is at most 3H+3 throughout. If H ≤ 21,844, every node index and every strip index plus one stored in the lists fits in `u16`. Casting preserves the exact ID at each operation. Induction on cuts gives identical widths, words, endpoints, every residual arrow and marked output. On larger H the constructor dispatches to the original wide endpoint after the usual strip census. This bound charges one comparison per admitted block. Width and word operations use the original source, including arbitrary multiple-cycle inputs. A worker that encounters both representations can retain both sets of scratch capacities. Peak process RSS still requires measurement.

All 383 blocks on the archived Wikidata run front satisfy the bound. The largest 3H+3 is 15,795. The largest measured geometry has 12,836 slots including the sentinel, corresponding to 308,064 bytes with wide nodes and 205,376 bytes with narrow nodes. The corpus total is 2,669,132 endpoint steps over these blocks. Those numbers price node fields only. They exclude vector spare capacity and other buffers. Some of the 383 blocks route through LazyCells under opend's density gate. The smaller arrays may improve L1/L2 locality. Zero-extension, altered code generation and retained capacity can offset that saving. `prepare.py` generates the candidate's two private source files from hash-pinned inputs. `check.rs` compares the marked bytes with a separate dense stable-LF loop and compares every published structural counter and output against the original queued Open constructor. For `L=[0,1,0]` and primary 1, inverse-LF moves to row 2 and the forward bytes are `[0,1,0]`. Exactly three backward LF steps reversed would give `[1,0,1]`, since the marked cycle has length two. The oracle traverses the stable inverse forward. Its exhaustive binary columns cover all marks, three widths, short and multiple cycles. Large columns hit both sides of the H boundary, alternate the live scratch representation, and exercise the cap at 127 records with the primary inside a long run. The scorer operates on the complete decoder and separately checks RLE1, valid and corrupted input, block CRCs and combined CRCs.
