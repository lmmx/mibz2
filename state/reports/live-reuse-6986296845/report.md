## 1. Owner, reachability and wrap

A strict win changes the other front and leaves the winner at the same front. The next cut therefore uses the surviving letter in the same operand position. It can win again or be consumed by the next loss or equality. Only the whole-front path can close, so a closure cannot intervene while a strict winner remains on its front. A rule's use sequence is contiguous in the logical cuts, and its last parent is the cut exhausting it. After that there is no live cell with that stored identity.

A stored-rule child forces the product into the rule region. This holds even when its length is below the short cutoff because the mark bit remains in the product's packed length. Thus there is no hidden non-stored logical cut between two successive uses of the same stored rule. A saved pair from the next stored parent detects survival by same-side equality. A tie exhausts both and produces no deferred command. Strict cuts retain at most one operand. Comparing by string, by length or across non-unique long-rule descriptors would invalidate this certificate.

For an active letter of width w and word length l, use mass w·l. A cut of width s removes the same mass s·(lA+lB) that its new cell adds. Only closure removes positive mass. Initially there are n rows of length-one labels and the marked row has width one. Its descendants keep width one. If its final length is p=n then no other component can have closed or remain live. Every stored identity reaches the marked root through last-parent edges, whose indices strictly increase. These choices form one rooted tree over stored rules. A marked identity occurs once in the root unfolding because weighted marked multiplicity is conserved from the original singleton. The marked-child walk fixes the same physical cut one byte after the mark. A circular factor can cross the cut only on that spine. Each unmarked destination is within the emitted period.

## 2. Partial periods and exact output

I rebuilt both shipped-cutoff examples with an independent two-order scalar induction. For L=11 followed by 33 zeros, primary 2, p=35 and the 17-byte copy from 17 to 0 is exact. For L=11 followed by 34 zeros, primary 3, p=18. The three stored rules in birth order are:

| Rule index | Length and mark | What happens |
|---|---|---|
| 0 | 17, unmarked | Used first in rule 1, then exhausted by rule 2. |
| 1 | 18, marked | Bottom win uses rule 0 and keeps it. This is the marked root. |
| 2 | 18, unmarked | Equality consumes rule 0 outside the marked root. |

The unguarded algorithm tries to anchor rule 0 at unreachable rule 2. With p<n, choose the shipped writer or the studied overwrite-on-reach fallback before any destructive scan. For overwrite-on-reach, initialize only the root as reachable, skip every NIL parent in descending order, and offer positions only from selected reachable parents. Before a rule's own reverse visit, all possible reachable parents have already offered. The chosen occurrence is therefore nested inside a selected parent. In increasing birth order, every child's selected expansion is complete before its parent's copy, independent of whether the selected source has a larger address. The emitted period agrees with dense stable LF and repeats to the known length n under the shipped doubling loop. Keep the existing RLE1 and CRC handoff. The same argument covers a root literal and a block with no long rule.

## 3. Source readiness and in-place bounds

At the end of the reverse pass the output is partitioned into written literal spans and disjoint holes for deferred copies. Any hole within the selected source of a command from parent j belongs to a lower-index parent in that child's owner subtree. Commands run in increasing parent index. Induction over that scan proves source completeness in both spatial directions. Two occurrences of one rule cannot nest, since that would make the rule its own strict descendant. Their spans are disjoint, so a later-address source is valid once filled. The copy count and byte volume stay the same as with minimum-position choice.

The command cursor starts past the last rule. Before reading parent j the cursor lies above j. After loading both operands, the single possible command can occupy j or a higher already-read record. The carried next operands live independently of that storage. With 16-byte stride an 8-byte descriptor and a 4-byte destination occupy offsets 0–11, leaving four bytes untouched. The positions fit 32 bits because the block is capped at 900,000 rows. The read and write bounds hold for the final compacted suffix. This argument covers the 16-byte rule layout shared by ordinary eager and lazy Cells. A packed W12 implementation and any caller that retains the grammar need their own check.

The independent byte-buffer audit writes actual bytes, tracks per-byte coverage, uses the actual cut type and a separately enumerated last-use index as checks on descriptor equality, and packs commands into 16-byte metadata records. It checked ten Wikidata and six prose records, all against independent dense LF. There were 44,899 later-address copies in those 16 records, including 4,608 on frozen. The frozen mark offset is 289,568 and the rotated output SHA-256 is f87e5caa2d5f0df9d5958fe60901e2023ae04ac406603d4c1584c8bb4017fbd6. All six action fields match the published sample rows. With R stored rules, M marked, J unmarked rule edges and K=J−(R−M) deferred copies, the baseline's two sweeps read 2R position slots, including NIL marks. Unmarked rules supply two operand-pair reads. The two marked passes after mark location supply the corresponding reads on the spine. Minima produce a read and a write per J, and the forward long edge needs another position read. Total 6R+3J. The candidate reads one position and one pair per R, assigns one position per rule including root, and pays five accesses per copy: two fields stored, two reloaded, one source position read. Total 4R+5K. The original initialization is omitted and two carried operands and every tested long edge are charged in the candidate scalar ledger. Branches get a unit price, with no dependent-load, prediction or cache model. Mark location and payload output bytes are common. The eager-admitted and lazy-admitted populations intersect, and these are prices on the registered per-block grammar and population flags.

The minimum priced saving across the 233 is 76,157 units. The first block would go nonpositive after about 2.719 uniform extra units per rule in the model. Pricing a third field in every command both ways still leaves a minimum 59,445. These are source-level margins with explicit prices, not spare machine cycles. The removed passes stream through the rule region. The candidate writes commands back into those lines, changes destination order, can copy from much later addresses and changes positions and branch locality. Store ownership, spill traffic, dependency latency, cache and DRAM accesses, and multi-worker contention can reverse the result. A fused candidate with the same output and a paired phase/full-decoder comparison is needed for timing. ## 6. Prior art and disposition

Conrad and Wilson describe expanding an SLG symbol on first encounter, remembering its output address, and copying repeat occurrences. Navarro's grammar-tree discussion similarly picks one representative expansion per nonterminal and treats other occurrences as references, and places bidirectional references in the broader literature. Ordinary left-to-right LZ77 uses an earlier source. Here a topological parent order permits later sources. A general acyclic grammar can select the latest *reachable* parent by testing a position or seen marker; that part needs no Cells-specific geometry. What Cells supplies is the same-side next-descriptor certificate without an old-position lookup, plus at most one defer per parent under unique identities. The latter fits commands in the already-consumed rule arena and produces birth order without sorting. [GLZA, §2.1](https://encode.su/attachment.php?attachmentid=4240&d=1459295189) · [Navarro, §3.4](https://users.dcc.uchile.cl/~gnavarro/ps/acmcs20.2.pdf) · [LZ77 definition](https://pmc.ncbi.nlm.nih.gov/articles/PMC10613516/)

Advance the writer as a standalone candidate if measuring it. Keep the p<n guard and current writer fallback initially. The unresolved question is whether changed source locality, extra dirty metadata and code generation pay for fewer field accesses. No native code, candidate timing or full compressed-corpus regeneration was performed in this review.
