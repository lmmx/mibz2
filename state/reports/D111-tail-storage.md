## Bounds and lifetime
Let L be the final output Vec's length, S=layout.shift, T=layout.tail. reserve(T) ensures capacity >= L+T before a pointer is obtained. A shifted access at offset a has physical address base+L+(a-S); all dereferenced bottom/rule addresses have S<=a and a+width<=S+T. Integer read/write helpers use wrapping_add; send_rules also returns into the allocation with wrapping_add before in-bounds add operations. Provenance remains the tail allocation's.
For r letters and b budget, top storage is 20r; arena has 16+256+16+16b+32 bytes; bottom storage is 8r; rules reserve 16b+16. GAP separates debug regions. Every cell decrements a checked remaining budget before materializing at most one 16-byte rule; fixed letter slots are reused, not grown. Staged rule alignment rounds upward before reserving the tail. The API boundary restricts b<=n<2^24 and records<=n, bounding even 32-bit arithmetic; explicit u32 offset rejection remains.
Independent Python checks used exact PAD=4096, BPAD=128, both GAP values, staged/nonstaged alignment, lengths 0/1/7/128/900000, n=1..127/900000/2^24-1 and budget/letter boundary combinations: 12,640 layout translations passed. This is arithmetic evidence, not a Rust provenance test.
The writer's out is s.ll, while the tail is decode_block's final output. Distinct mutable Vec arguments own disjoint writable allocations. Neither induction nor writer changes the tail's length or reserves it again. finish/RLE appends only after the kernel returns and no pointer survives. If the final output initially fills capacity, reserve grows before pointer creation; if RLE later fills or reallocates it, all rules are dead. There is no requirement that RLE expansion fit the previous tail reservation.
The lazy feature keeps rules in the kernel allocation and uses unshifted tail streams/pool; staged keeps rules in the shifted tail and retains the same-thread fence guard. These adaptations were source-reviewed, not covered by an assumed carry-forward of D110's binary evidence.
