## Attempt marker

**A process crash or kill after marker creation consumes the attempt on the designated i9 with the registered checkout and queue state retained.** The recipe writes `timing-started.txt` before launching the first `ab run`. The guard treats the marker's presence as sufficient even if there is no result, finish stamp or archive. A setup stop leaves only `started.txt` and the build or identity issue can be repaired. A missing or unreadable fresh evidence ref still refuses a new run. [Recipe](https://github.com/lmmx/mibz2/blob/4bb9e31963b20ab2c359bb89afaf81b8b537ba35/.just/bench.just#L2335) · [Guard](https://github.com/lmmx/mibz2/blob/4bb9e31963b20ab2c359bb89afaf81b8b537ba35/bench/open_port.py#L538)

I ran the pinned guard against a readable scratch evidence branch and a previous run directory. It allowed the setup-only case. A stub wrote the exact timing marker, then killed itself with SIGKILL before producing a bundle. The next guard invocation refused. The normal queue separately acquires an atomic per-recipe, per-ready-commit marker before invoking the recipe and retains it on failure. A documented pre-timing setup repair can be requeued through the usual review and ready-pin process once the first process is confirmed stopped before `timing-started.txt`. The recipe guard on its own checks recorded state. The one-attempt ruling uses the registered single-i9 queue and the same retained checkout. [Workstation waiter on master](https://github.com/lmmx/mibz2/blob/3addea7226e4270d68a09f54b13d40dd56dc115a/bench/await-submit.sh#L146)
