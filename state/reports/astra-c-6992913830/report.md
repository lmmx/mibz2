# Astra C · independent record review

**PROCEED as a research record.** The headline arithmetic, frozen byte counts and ten dense checks trace to pinned generators and match the replay. The traffic result warrants a native performance question, with opposite signs for two different model observables.

I froze the [evidence baseline](https://github.com/lmmx/mibz2/blob/0f5e381a07fd61aa220ba9edc297b6adf76fafec/state/reports/astra-c-6992913830/baseline.md) before opening the main journal and its summary. The review uses the pinned #601 record, its linked comparator evidence and the ten input blobs from data release `2e4b34e0`. The input files' Git blob hashes match that release. I did not consult the other Astra branches.

## What the construction establishes

Within a first-column byte bucket, stable select is increasing. The preimage of an interval under it is an interval. Along a common spelling, distances between ordered rows never decrease, so a common additive exit forces each intermediate select to preserve their distance. This identifies a maximal sequence of translated base pieces. On a section miss, intersect those translated domains and the terminal preimage of the section. Each intermediate piece then has the same membership in the section, and the terminal clip certifies the first return. A copy refers to bytes already in the readable output prefix. Those two invariants imply that a hit can advance by the same displacement after copying the same word. The last output can stop within a hit or miss. The small replay includes the `100` witness where dropping the final exit clip incorrectly admits an origin whose exit lies outside the section. It also checks arbitrary marks and short periods. The full-period occupancy bound applies to this particular table representation. Its proof uses the fact that the marked orbit queries each possible section row, and at most the final miss can leave its queried row unpublished.

These are proof and structural count claims. The histogram and directory still build a whole-column one-step index. A completed prefix remains readable. Arbitrary byte/exit opportunity counts from the free-key screen describe a distinct diagnostic. A native decoder, write-only streaming implementation or general lower bound on reconstruction work was outside this review.

## What the model can tell us

The generator replays an address stream for an aligned packed layout using independent cold, fully associative, write-allocate LRU caches with 64-byte lines. Transfers count every fill and dirty writeback, including a final dirty drain. A demand-read fill is already a subset of fills. All traces end at marked output. RLE1 and CRC are listed as common logical work outside that replay. The section's setup, table clear, direct walk, lookups, publication and source/destination touches are charged. The comparator remaps archived induction operations and the one-scan writer onto assumed addresses. It is a source-level comparator, with no native cache trace or simultaneous-worker simulation.

At 256 KiB, the matched lazy comparison has 369,150 fewer write-triggered allocations and 845,299 fewer dirty writebacks. Against those savings it has 217,475 extra demand-read fills. A model charging one unit per transfer plus an additional λ per demand-read fill therefore changes sign at λ = 996,974 / 217,475 ≈ 4.584 at 256 KiB. At 32 KiB this threshold is 934,246 / 1,507,967 ≈ 0.620. These are sensitivity ratios. Dependence, concurrency, prefetch, associativity, copy ordering, traffic from the rest of the decoder and actual sharing among workers can change the result. The 2 MiB and one-seventh-of-20 MiB models are capacity probes. Their events are not measured occupancy or cumulative DRAM traffic. The journal's bandwidth opportunity is conditional on those modeled savings carrying into hardware. A lower line total and more dependency-sensitive demand fills can coexist with either wall-time ordering.
