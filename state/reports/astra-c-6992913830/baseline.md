# Astra C · evidence baseline before reading the record summary

From the pinned implementation, line model and CSVs, a byte-section cursor emits a marked spelling directly until it reaches a chosen interval. At an unseen section row it emits a return word, intersects shifted base pieces and clips origins so every certified exit remains in the section. At a hit it copies already emitted bytes and uses the row displacement, which belongs to the interval certificate. The construction has executable small-case checks and a ten-input dense marked-output comparison in the section driver.

Frozen block 0 has 899,931 marked bytes. The section driver counts 206,638 direct bytes (6 prefix plus 206,632 walked) and 693,293 copied. These are algorithm counts. The section driver checks direct plus copied equals the output length and asserts byte equality with an independently constructed dense stable inverse before accepting each output row. RLE1 expanded digests are separate. The frozen output has an extra pinned size and digest assertion.

The fair headline join is nine LazyCells-admitted blocks. At 256 KiB the section model charges 1,686,483 line transfers versus 2,683,457 for the matched lazy comparator, or 37.1526% less. Demand-read fills are 1,092,392 versus 874,917, or 24.8566% more. A ten-output check and nine-block traffic comparison have distinct denominators. Fills are allocated line misses, reads are one subset, and dirty lines include the final flush. This is a cold, fully associative, write-allocate LRU replay with disjoint packed-address regions and independent capacities. A line transfer names a model event at the 256 KiB capacity, not a transfer of 256 KiB. With approximately 4.584 saved model transfers per additional demand-read fill, an assumed extra price above that ratio reverses a linear weighted comparison. No real cycles, cache misses, DRAM bytes, speedup or deployment verdict follow. The comparator reconstructs addresses from archived induction/owner records and is a model, not a native trace.
