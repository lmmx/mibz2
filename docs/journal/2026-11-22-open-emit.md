# Two-ended and register-relay emission in Open

**Direct manual assignment from Louis (outside `coord.py` dispatch).** Base `8ff1187`, mibz2 0.5.11.

**Keep RegRelay6 with the original 135,000-row gate.** On the four-worker whole-corpus confirmation its time relative to Fused-XOR, normalized to each arm's paired master, was **0.973 [0.963, 0.984]**. RegRelay6's own interval against master includes parity. Its clear gains were the dense four-worker pass (0.846×), the six-block four-worker pass (0.946×) and the one-worker whole corpus (0.964×).

Fused-XOR shortened the corpus emit to 0.773×, but paid for zeroing the edge table and updating both ends of every queued edge. On authenticated blocks 0 and 2 the faster emit still produced a slower full decode. RegRelay6 keeps master's wiring and forward walk on smaller tables. On larger tables its six lanes overlap the cost of replaying scouted edges. The additional worker memory buys indexed lengths and segment boundaries for that path. Only RegRelay6 enters the production build. The journal archives the measured Fused-XOR port and its tests.

## Method and inputs

Direct manual assignment from Louis. Base `8ff1187af6a920f7d57fd338680db3a5633a3ac5` (0.5.11). The two candidates use master's elimination, word inlining, admission and fallback.

The release harness compiles four kernels into one binary. They are master, an A/A copy of master, Fused-XOR and RegRelay6. It uses the crate's pinned rustc 1.99.1, its default release profile and the system allocator. The host is an AMD EPYC 9V45 KVM guest with five visible CPUs and a four-CPU quota. W1 is pinned to CPU 2 and W4 to CPUs 0–3.

Each of 24 rounds starts a fresh process per worker count. The six possible arm orders rotate across rounds and each pair reverses its starting order on alternate rounds. At W1 we warm each block on both kernels, then alternate decodes in ABBA order and take the within-round 10th percentile. There are 12 observations per arm and block on the six and dense suites, two on the full corpus. The W1 suite figure sums block times. At W4, four persistent workers each decode the whole suite, starting at different blocks. A barrier before each pass makes the workers run the same arm together. Each worker warms both arms, then measures eight passes per arm on the six and dense suites and one per arm on all 431. The headline pass is the median over worker times as in #692. The slowest-worker row also records time to finish the pass. No compressed-file I/O, front-end decoding or output hashing is timed.

Emit-only times use independent, prebuilt representations for the paired arms. Each emits and checks the same output before timing. They exclude wiring, word inlining and length-table construction. The 233 blocks admitted to Open contribute to the corpus emit sum. The whole-kernel figures use the production OpenCells entry points, including fallback on refused blocks. Intervals are two-sided Student t intervals on 24 paired log ratios (23 degrees of freedom). The first four-worker A/A corpus pair differed by 6.4%, so the sample size was fixed at 24 early in the run. No gates or kernels were changed. Times in the CSV are medians across rounds. A ratio below one means a shorter time. The full-corpus four-worker pass was the primary selection measure. Because the one-pair corpus passes showed much more variation than the eight-pair short suites, a follow-up fixed before its first run repeats only the primary measure in 12 additional fresh processes, with **12 paired passes per worker and arm in every process**. The only harness changes select the full corpus and set repetitions. Its interval uses 11 degrees of freedom. Both experiments are reported separately.

The six raw columns come from `data/admitted-bwt` at `41c03a5b22d630adb171231f5225da348b8055af`. All six sizes and SHA-256 digests match `admitted-bwt/manifest.json`. Their filenames use large-block indices. In the raw data the six suite IDs 10000–10005 denote blocks 0, 2, 85, 143, 210 and 207 in manifest order. Dense rows 41, 56, 165, 270 and 278 use zero-based indices into the full corpus. The twelve authenticated dump windows rebuilt 431 blocks, 209,700,196 decoded bytes, with compressed SHA-256 `82f65ace0731962d04443bbda4cebfdccd336106049751060f477941c2c29915`.

## The walks

- **Fused-XOR.** Queued, narrow tables with at least 65,536 retained rows store each row's predecessor XOR successor under the word code. Wiring zeroes the existing table, folds in both neighbours in a single pass over the queues and saves the predecessor of the mark. Two independent cursors write into opposite ends of the final output. Each marked-cycle row supplies its word once. An odd cycle consumes its middle word once. For a shorter cycle the suffix moves next to the prefix before repetition. Small, wide and unqueued tables keep the forward walk. Cycle 22 measured the cost of a second wiring pass. Cycle 24 measured the staging and stitching cost of four cursors. This is the original two-cursor fused version from cycle 17.
- **RegRelay6.** The fixed gate is narrow codes and `m >= 135_000`. One lane emits directly while five scalar scout cursors measure cut-to-cut segments. The direct lane skips completed segments or takes a scout's partial work. Six scalar emitters fill those output ranges and repair boundaries after their 16-byte stores. The tail drops inactive scouts. The scout-length table is built after master's `inline_words`. A length reaching the 16-bit sentinel uses serial emission. There are at most 256 cuts and each contributes at most one deferred task, so 256 entries suffice for each task array.
- **Relay8 (#705)** fetched about 1.87 edges per retained row because seven of eight lanes scouted words later fetched again by emitters. Its reported i9 ratios were 0.994, 1.013 and 0.995 at 6, 8 and 10 threads. A trades that second walk for a construction-time read/modify/write per neighbour. B still pays for replayed scout loads. Cycle 26 reported about 1.82 visits per row. It also removes dummy loads, uses six scalar cursors, and gates the extra work to larger tables. Its published four-worker whole-corpus ratio was 0.9951. The 0.9776 figure belongs to cycle 23's RegBurst6.

The prior measurements and implementations are recorded in [Kitchen Sink cycle 17](https://github.com/lmmx/mibz2/blob/research/carbon-kitchen-sink/docs/journal/2026-11-21-carbon-kitchen-sink-cycle17.md), [cycle 22](https://github.com/lmmx/mibz2/blob/research/carbon-kitchen-sink/docs/journal/2026-11-21-carbon-kitchen-sink-cycle22.md), [cycle 24](https://github.com/lmmx/mibz2/blob/research/carbon-kitchen-sink/docs/journal/2026-11-21-carbon-kitchen-sink-cycle24.md), [RegBurst6](https://github.com/lmmx/mibz2/blob/research/carbon-word-transport/docs/journal/2026-11-21-carbon-cycle23-regburst6-native-win.md), [RegRelay6](https://github.com/lmmx/mibz2/blob/research/carbon-word-transport/docs/journal/2026-11-21-carbon-cycle26-regrelay6-win.md), [Relay8](https://github.com/lmmx/mibz2/blob/perf/open-relay8/docs/journal/2026-11-21-open-relay8.md) and [the #692 protocol](https://github.com/lmmx/mibz2/blob/8ff1187/docs/journal/2026-11-21-open-memory-diet/drive2.py).

## Memory and exactness

Fused-XOR changes neither vector capacities nor the kernel's 352-byte object. Additional worker heap and staging storage are both 0 B. Its cursor state consists of scalar locals. RegRelay6's kernel object grows from 352 to 376 B. The additional heap is one u16 per dictionary code to give all five scouts an indexed length including long words. Its measured maximum retained capacity was 7,782 B per worker across the corpus at 1, 4 and 10 workers. Its fixed stack arrays hold task boundaries, saved prefixes and cut state. In the release bzcat disassembly, master's walk reserves 168 stack bytes after saving six registers. A reserves 248 (+80 B for the two-ended walk). B reserves 232 (+64 B), and its relay function reserves another 10,408 B plus six saved registers. These are function-frame sizes on this build. Neither candidate allocates an output staging buffer.

Both candidates passed the new emit tests against the independent serial reference. The tests vary output lengths across 15/16/17 and 31/32/33, long and short words, odd and even meetings, one-row cycles, disjoint cycles, periodic repetition and truncated segments. Both candidates and the control matched Plain byte-for-byte on all 431 corpus blocks and all six authenticated columns with fresh and reused kernels. A separate forced-Open pass fed all 431 columns as run records, including the 198 normally sent elsewhere, and matched Plain for both ports in fresh and reused kernels. The Fused-XOR mutation dropped the middle word and failed the one-row case. The RegRelay6 mutation omitted the saved-boundary restore and failed at seven rows, stride three, mark six and 31 output bytes.

Both production builds passed `taskset -c 0-3 cargo test --release` (248 tests) and `cargo clippy --release --all-targets -- -D warnings`. The initial unpinned A run failed only the existing topology assertion (five visible cores, four CPUs available by quota). Each port passed all 338 moonshot correctness cases with `Candidate = mibz2::bwt::OpenCells`, including the authenticated corpus. At each of 1, 4, 8 and 10 threads, each release `examples/bzcat` matched `bzip2 -dc`'s SHA-256, `3f075e30f4f8c73414150655afbf57caa2647c7927e743fc0635b4912d65cdaf`. These are end-to-end correctness checks. The in-process kernel tables directly exercise Open irrespective of the worker plan.

## Reproducing the comparison

Use three worktrees. Check out the master base in the reference and A worktrees and this PR in the B worktree. Restore A with `gzip -dc "$journal/fused-xor.patch.gz" | git -C "$candidate_a" apply -`. Run the installer once in the disposable reference worktree. The raw archive holds the per-round paired samples in nanoseconds. The CSV files give median times in microseconds, geometric mean ratios and their 95% intervals.

```sh
python3 "$journal/setup.py" "$master" "$candidate_a" "$candidate_b"
cd "$master"
cargo test --release --lib --no-run
# Use the test executable printed by the preceding command as $binary.
python3 "$journal/run.py" "$binary" "$corpus" "$six" "$rounds"
python3 "$journal/report.py" "$rounds" > measurements.csv
ADMIT_BZ2="$corpus" MIBZ2_ADMITTED_BWT="$six" MODE=parity ROUND=0 \
  "$binary" open::trial::measure --exact --ignored --nocapture
ADMIT_BZ2="$corpus" "$binary" open::trial::memory --exact --ignored --nocapture
python3 "$journal/mutate.py" "$candidate_a" "$candidate_b"
git apply "$journal/confirm.patch"
cat "$journal/forced.rs" >> src/open/trial.rs
cargo test --release --lib --no-run
ADMIT_BZ2="$corpus" "$binary" open::trial::forced_parity --exact --ignored
python3 "$journal/confirm.py" "$binary" "$corpus" "$six" "$confirm_rounds"
python3 "$journal/report.py" "$confirm_rounds" > confirmation.csv
```

Build the authenticated corpus with `bash bench/moonshot/corpus.sh` and extract `admitted-bwt/` from the data branch above. The driver validates all seven hashes before timing.
