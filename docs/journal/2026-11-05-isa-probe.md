# 2026-11-05: The ISA level's worth per stage: x86-64-v3 against x86-64 (closed)

**The question.** The decoder dispatches only three kernels by CPU feature at run time: the CRC
(PCLMUL), MTF and RLE1 (AVX2). Everything else compiles for baseline x86-64, which is what the
wheels and crates ship: the Huffman decode's bit extraction, the build and the walk. What would
BMI2, LZCNT, MOVBE and AVX2 everywhere be worth to each stage?

**How it was measured.** Research PR #201, never for merge. It built the same source on both arms
of the PR bench. Only the head's build step set `RUSTFLAGS="-C target-cpu=x86-64-v3"`; the base
stayed at x86-64. The run was 42048643495: EPYC 7763, 10 paired rounds, the same bytes on every
corpus. The bench comment is kept as `2026-11-05-isa-probe/bench-42048643495.md`.

**The rule,** registered in the PR before the run:
- a stage that gains 5% or more beyond noise, or `wikidata` 1-thread CPU falling 2% or more,
  gets a multiversioned clone behind run-time dispatch, as its own PR;
- if neither holds, ISA-level dispatch for the scalar stages is closed.

## Result: closed

**Whole decoder, `wikidata`:**
- 1 thread: +1.0% (+0.0, +1.9), slower.
- 2 threads: +1.9% (+0.1, +3.6), slower.
- 4 threads: −1.0% (−2.3, +0.4), no change.

**Per stage, 1 thread** (`phases`, c/B, head over base):

| stage | base → head c/B | change |
|---|--:|--:|
| scanner (Huffman) | 1.23 → 1.20 | −2.4% (−2.8, −2.1) faster |
| MTF + RLE2 | 1.99 → 2.37 | **+19.3% (+18.8, +19.8) slower** |
| T-vector build | 2.17 → 2.07 | −4.5% (−5.1, −3.8) faster |
| walk | 4.39 → 4.51 | +2.5% (−1.3, +6.5) |
| RLE1 | 0.29 → 0.29 | +0.5% |
| CRC | 0.26 → 0.26 | +0.8% |
| total | 10.33 → 10.72 | +3.6% (+1.8, +5.4) slower |

**No stage reaches 5%, so no clone is made.** What the probe leaves is a set of bounds:
- **the build:** an ISA-dispatched clone could buy at most −4.5% of it, about 0.9% of 1-thread
  time;
- **the scanner:** at most −2.4% of it, about 0.3%. A multi-symbol Huffman decode has to come
  from fewer lookups, not from BMI2;
- **the threshold is not moved after the fact.**

**MTF is fragile to codegen.** Its AVX2 kernel is chosen at run time on both arms. The global
target changes how the code around the kernel compiles, and the stage loses 19%. Any change that
alters codegen globally has to read the MTF row before anything else: PGO, a toolchain bump, a
different LTO setting. It is also a lead for the MTF work: something in the stage's codegen
moves by a fifth with the compilation context alone.
