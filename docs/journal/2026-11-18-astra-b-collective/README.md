## Run the checks

From the repository root, with Python 3.10 or later, Git, tar, sha256sum and rustc on PATH, the following commands use a temporary directory. The extraction/check run used rustc 1.90.0. It invokes the pinned crate directly and has no package dependencies. Leave Python assertions enabled.

```sh
study=docs/journal/2026-11-18-astra-b-collective
tmp=$(mktemp -d)
datarev=a0692452b67ec3a8833e1fc4adf58a4f09cd9e6a
git fetch --depth=1 --no-tags origin "$datarev"
git archive "$datarev" windows/wikidata-20261019 | tar -x -C "$tmp"
python3 "$study/rebuild.py" "$tmp/windows/wikidata-20261019" "$tmp/wikidata.bz2"
sh "$study/reproduce.sh" "$tmp/wikidata.bz2" "$tmp/recheck"
```

An existing corpus with SHA-256 `82f65ace0731962d04443bbda4cebfdccd336106049751060f477941c2c29915` can be passed directly to the last command. The small suite alone runs with `python3 "$study/check.py"`. The full script compares regenerated CSV and JSON files byte for byte.

The window rebuilder verifies each window, assembles complete blocks with their original bits and checks the final corpus digest. The reader appends a small read-only main to a temporary copy of the pinned crate root, giving it access to the ordinary `runs::Runs::records()` accessor. It runs the shipped scanner and MTF/run front, copies the little-endian two-byte records and exports block boundaries, CRC and primary. It reads all blocks to number the 233 large ones. LF discovery uses only the selected block's capped records and primary. The first block's 89,730 entropy-decoded symbols give 56,386 capped records. The front is common work. No proposed shortcut uses an induction trace, finished grammar, dense permutation, decoded output or computed LF event to select itself.

The real checker independently rewraps each selected compressed block, decodes it with Python's libbz2 (including the CRC check) and compares the bytes to the reconstructed marked output after RLE1. It compares all six tile widths, the group constructor at width 2 and the queue constructor. The frozen one-block stream starts at bit 336 and has SHA-256 `e3bf5372b15885da138764a25bb2b7cd784ee3cbee1e664937647921ae3122b0`. [Per-block input manifests and digests](verified.csv)

## Cost model

All line counts assume 64-byte lines. Keep these three comparisons separate. [Executable ledger](ledger.py) · [Per-block numbers](ledger.csv)

1. **Scalar exception index.** Grant free discovery, tile matching, stable ordering, a row-to-index dictionary and a free writer. Charge only two separately aligned contiguous arrays, eight bytes per tile and eight per exceptional row for a successor and gap. Minimize $\lceil8K/64\rceil+\lceil8E_{\min}/64\rceil$ over the tested widths. Even the minimum pays one dependent successor per exceptional real row on a full-period block if traversing the explicit return list. A different storage layout, batched traversals, another grid, or a dictionary of exceptions have different costs.
2. **Aligned path bundles.** Model the binary searches on a sorted 4-byte start per clean group. The addresses come from the actual choices of left or right branches. Cold fully associative LRU caches of 512 and 4,096 lines give `B2_start_fills32` and `B2_start_fills256`. These are index-only counts. On frozen the remaining 11,206 interior transitions require a group payload, 5,667 bundles must be delivered, and 53,982 retained-input/transfer intersections produce 53,430 coalesced output bands. The initial per-byte seeks, payloads, head subtraction, residual construction, writer and output have additional cost. The individual-tile oracle is solely a check. Giving its result for free prices only the residual.
3. **Equal-byte range queues.** The staged layout includes a 12-byte retained-source record (original position, image, width and byte packed together), one 16-byte (entry, stop, compact exit, repeat count) record per occupied hash slot and a 12-byte coalesced residual record (destination, width, byte and repeat count packed together). Source order gives the residual source prefix. Each array is line-aligned and disjoint. A power-of-two index of at least twice the number of inserted ranges is reserved at exact final capacity for the model. Clear each key, use high bits of the 32-bit multiplicative hash with multiplier 2654435761, linearly probe, and leave successful entries in place until the block ends. Only a new range start requires a lookup. The model credits the open output band with a single store while it coalesces.

   The trace follows list construction, range insertions, source reads, range lookups and residual stores, then a sequential read of the completed residual. In the two ideal write-allocating caches, transfers count fills plus dirty evictions and final dirty lines. The trace omits input reads, byte histograms, queue and cursor state, allocation, rank-order preparation, induction, word storage and output. The frozen range index incurs 10,952 probes for 4,640 insertions and 4,640 lookups. A fragment's end supplies the next lookup key when splitting an input band. The queue itself performs 6,996 fragment pops. Refills, probes and logical record operations are structural counts. Cache figures describe only this layout. They do not measure the i9's DRAM traffic.

### Crediting the residual induction

For full-period real blocks put $C=E+T+B$ for equal, top-win and bottom-win cuts, $D=1$ for the marked closure, $H_t=E+D+B$, $H_b=E+D+T$. Let $r$ count initial marked bands, $r_t,r_b$ count top-first and bottom-first original bands and $P$ be peak lazy slot pairs. Let $V=3C+E+3T+4B$. Counting the pinned eager hint-address reads yields $6(H_t+H_b)+V$ geometry fields. The lazy count is

$$5r+4(H_t-r_t)+3(H_b-r_b)+2(r-P)+2r+V+2E.$$

The first term accounts for the two original streams, the next two count slotted refills, the next two cover reused/free and newly assigned slots, and the final terms cover placement and equality release. The word ledger counts $2C+2(C-R)$ fields for $R$ stored joins. The observed uncontracted totals agree exactly with both models in the pinned source-level trace on every block. [Historical traffic census](../2026-11-18-cells-endpoint-sweep/traffic.csv)

For a conservative screen, grant the residual kernels their initial sorted orders and usable word descriptors for free. Compare the geometry and word-field savings above. Additionally credit eight eager or six lazy setup fields per net input band saved, matching the leading coefficients of the historical setup models. This defines `eager_field_credit` and `lazy_field_credit` for the byte-queue contraction. For the staged source and residual, count a whole read or write of a 12-byte record as one operation. Even these two arrays alone exceed the credit on each tested block. A fused decoder would need its own ledger.

A concrete alternative for ordering a general residual has one bit per row marking an exclusive bottom end minus one. Clear $M=\lceil n_{res}/64\rceil$ words, set $r$ bits by read/modify/write, build one prefix count per word, then read each band's mask and prefix to obtain its bottom rank. This adds $3M+4r$ field operations, with $8M+4M$ array bytes, before the final scatter. This is a constructive price for furnishing the required order. The bitmap is omitted from both the preceding free-order comparison and the cache trace.

The producer still reads the capped records and needs a per-byte row histogram to obtain LF translations. After a histogram, source ends and image starts are computed in one further run scan with 256 cursors. The code's diagnostic arrays and Python allocations do not predict a native footprint. A complete implementation must also emit $n$ bytes, supply long-copy source reads and, on periodic blocks, repeat the marked period. No timing result from this environment enters the decision.
