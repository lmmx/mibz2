# Astra A · Inverse BWT by learning shortcuts from the output

18 November 2026. Independent investigation for MONODROMY and the Researcher. [Draft PR #599](https://github.com/lmmx/mibz2/pull/599)

**Result.** Two consecutive completed output spans can teach the inverse how to emit their concatenation and where to resume. Keeping each original run image intact gives a particularly small dictionary. When a prospective extension crosses its next domain boundary, that word can be retired permanently. The selected algorithm matched every pre-RLE1 byte on all 233 large Wikidata blocks. In a 20 MiB shared-cache model it reduced memory-line transfers by 20.5–20.9% against lazy Cells with seven through ten workers. [Proof](shortcuts.md) · [Results and limitations](results.md) · [Reproduction](#reproduction)

The main risk is the serial path through the dictionary and the much larger number of short output spans. Frozen needs 117,399 spans. Most of the 40,731 copies are 16 bytes or shorter. At 32 KiB the candidate incurs more read fills than lazy Cells while saving write allocations and writebacks. Independent hardware timing remains open.

## Starting point

The input available on mibz2's run route is a primary row and a stream of 16-bit records with lengths capped at 127. Huffman, RUNA/RUNB and MTF decoding precede it. An expanded last column, a suffix array, a finished grammar and an oracle spelling each have a construction cost. The reference on a full-period block is the eager or lazy induction followed by the one-scan owner writer. Short periods and refused blocks have different paths. The target is a block worker sharing memory bandwidth with six to nine other workers on the i9-10900K.

On the frozen block earlier work finds 92,570 cuts, 28,710 long rules and 9,628 deferred copies. Earlier proofs fix the copy volume for any expansion-once traversal of that grammar. The first-occurrence writer illustrates the cost of a dependent read even when fewer fields are accessed. The verified arrival schedule pays for ordering. The boundary-orbit profile predicts work in the two constructions tested. Its published scope leaves other inversions open. An earlier delimiter parse already built a phrase column by refining suffix intervals and paid separately for dictionary discovery.

## First experiments

* Can predictable byte adjacency recover whole chains from a bigram census? Count what the census determines and exhibit ambiguities before pricing a traversal.
* Can a reversible substitution produce an ordered BWT of tokens directly from old runs? Test a simultaneous substitution of ordered, disjoint byte pairs, including recognition, the rank of the surviving primary, and the physical fragments processed.
* Can information about a whole repeated phrase be obtained by testing a candidate from the decoded prefix or a fixed dictionary? Check what a verification query must establish, including its coordinate of re-entry.

The frozen block is large-block ordinal 0, stream block 1, primary 264,045. The comparison sample is fixed in advance at the ten archived large blocks numbered 0, 24, …, 216. The comparison uses the actual eager and lazy admissions within that sample. The screen charges construction before crediting removed text rows.

## Frozen observations

The independently identified last-column hash is `db8764224ac4980112ddefbe85b8593f5236643fed71bf8f0b739567d4f2ac67`. The following are exact, pre-RLE1 structure counts. [Counter](early.py) · [Frozen row](evidence/frozen.csv) · [Counts by depth](evidence/frozen-levels.csv)

1. **One-byte context.** Intersect the sorted first column's byte buckets with the input runs, weighting each intersection by its length. This gives the directed adjacency matrix. Only 10,668 rows lie in buckets with a unique predecessor. Even the most frequent predecessor in each bucket leaves 565,756 exceptions. The primitive cyclic strings `001011` and `001101` have primary zero and identical bigram counts (00, 01, 10, 11 have counts 1, 2, 2, 1). They have different spellings. An Eulerian reconstruction from these margins needs occurrence-order information.
2. **Change the alphabet.** Give the prefix of the ordered alphabet closest to half the rows the low colour (inclusive frozen cut 95). Replace every adjacent low-high pair by one token. Such pairs are disjoint. For a low byte a, unpaired occurrences have a low byte following them, so their suffixes precede every pair (a,b), whose order is increasing b. Among surviving starts, comparison of unequal token streams agrees with comparison of their byte expansions. Drop precisely rows with high F and low L. At all other rows with predecessor b high, read the previous byte at LF(row). A low result a supplies (a,b) and a high result supplies b. The dense counter implements just this formula. In a run implementation the reads for each b advance monotonically through its first-column bucket. The 116,263 removed rows shrink 51,184 runs to 49,310 and grow 89 symbols to 391. A fast reduction in the mass of the output here gives little reduction in the number of records another pass would consume. A prior coloured-pair study also contracted disjoint pairs. The ordered cut gives an ordinary token BWT with inherited collation and avoids its general resort of both interval orders. [Earlier pair screen](../2026-11-18-switch-elimination/pair_screen.py)
3. **Cache entire output chunks.** Reading backwards from the primary, partition into aligned chunks of width 2, 4, 8, etc. Tail remainders at each level are free. There are 77,620 distinct byte words summed over these levels, yet 145,619 occupied maximal intervals on which both the word and its exit-row translation are constant. To see the difference, start with the maximal constant runs of L. On an interval of depth k, the exit map is increasing by one at each consecutive row. Split it at preimages of every depth-k boundary in the image to get depth 2k. An interior cut first separates adjacent rows at a step where their bytes differ. Conversely, a separation during either half makes the doubled spellings differ. Recursively computing each distinct occupied interval once requires one binary join for each of the 145,619 intervals, even with free recognition. This exceeds Cells' 92,570 joins by 57.3% before the base layer. The bound applies to this explicitly materialised dyadic parse. A factor reused at a different boundary can escape it.

The output-driven test learns a certificate for an entire phrase from material already emitted. Its ledger includes predecessor recognition, updates, dependent row advances and copies. [Shortcut computation](shortcuts.md) · [Full cost ledger](results.md)

## Further falsifications

The ordered token transform can be priced against the work its first pass actually removes. The favourable streamer counts one piece for an original run, one extra when a low run straddles the low/high first-column boundary, and each change of projected predecessor *within* a high run. It gets the coarsening of all high predecessors to one symbol for free. After projecting the primary (including its within-token offset), feed the token column to the same binary geometry.

|---|---:|---:|
| Ordinary Cells cuts | 92,570 | 1,236,053 |
| Token-column cuts | 89,528 | 1,176,998 |
| Cuts removed | 3,042 | 59,055 |
| Pieces processed to obtain the token column | 51,781 | 699,767 |

Even if token naming, digit expansion and the change of output alphabet are free, frozen needs a piece to cost less than 0.059 of a removed cut to break even in this model. All ten have more piece visits plus token cuts than original cuts. The token-column implementation checks 6,444 primitive-word and partition cases with an independently sorted token BWT, including 1,436 swallowed primaries. The ten-block dyadic screen finds 892,128 different byte words and 1,771,246 occupied exit certificates, against 1,236,053 Cells joins. The static bigram prediction has 5,694,534 exceptions among 8,999,915 rows. An adaptive LZ78 control on frozen produces 68,847 phrases with the byte spelling supplied and 121,699 on the run-identity itinerary that certifies an affine exit. Remembering just the last *partial* word per original forward domain, and falling back to its literal outside that word, costs 132,765 visits and 87,566 installations. Permanent whole-domain learning needs 117,399 visits and 25,283 installations. None of these figures charges an oracle spelling as input to the proposed algorithm. [Adaptive controls](controls.py) · [Frozen receipts](evidence/controls.json)

**Longest possible word on each original domain.** Trace one representative from the left endpoint of a wide domain. While the image's two endpoints still lie in one atom, its entire width takes the same step. Record the letters and final displacement, and use the resulting longest itinerary at each output visit. Grant the counter dense, constant-time atom and successor lookup. All frozen wide words together require 1,637,054 successful individual advances to construct, before failed tests. With the dictionary supplied, greedy consumption takes just 62,543 visits. Constructing words only at their first use leaves 203,267 additional advances on frozen, even after folding each discovery's first letter into the output visit.

In a unit model charging one per visit, single advance, installation or retirement, direct on-demand construction costs at least 265,810 on frozen. Adjacent-span learning takes 117,399 visits and 32,185 updates, totalling 149,584. Across ten blocks the direct count is 2,632,859 and adjacent-span learning takes 1,554,950 visits plus 374,149 updates. All ten favour adjacent-span learning at these prices. This comparison gives failed recognition and storage of the direct dictionary for free. [Executable control](maximal.py) · [Per-block receipts](evidence/maximal.csv)

There is also a collective construction of all the maximal lengths. Let the gap at g be between rows g−1 and g. At an original-domain boundary its remaining common itinerary has length zero. At an interior gap the length is one plus the length at Ψ(g). Every such step moves both neighbours by the same translation. The maximal itinerary for a wide domain is the minimum over its interior gaps. In reverse, a gap y has a predecessor precisely when L[y−1]=L[y], and that predecessor is LF(y) by stable order. Reverse walks from all boundaries are disjoint, so they compute each finite gap depth once. An unvisited cycle can take the block-length cap. This verifies every wide length from the direct calculation. On the ten full-period blocks the walks take exactly n−r steps per block, 848,747 on frozen and 8,309,431 altogether, before extracting spellings or emitting bytes. Charging one per enumerated gap already rejects that dense schedule. A construction that visits only the minima would have a different cost. ## Reproduction

From this branch run the following in a checkout with Git, Python 3 and NumPy, a C++17 compiler, Cargo and Rust. Supply a fresh scratch directory. The scripts fetch only the named historical data commits when absent and put extracted columns, oracle output, compiled programs and address traces in scratch. The final check compares every regenerated receipt byte for byte. Expect several GB of scratch space. The research examples compile with Rust 1.90.0 in the supplied workspace. The repository's own toolchain pin is also available to a normal checkout.

```sh
bash docs/journal/astra-a-reinvention/reproduce.sh /tmp/mibz2-astra-a-repro
```

The packed-input replay regenerated all 18 committed evidence files byte for byte. Their Git tree is `a246ecdc55c45cc52666526d0ec0c74657424335`.

The archive of original Wikidata windows is pinned at `a0692452b67ec3a8833e1fc4adf58a4f09cd9e6a`. The ten historical traces are pinned at `2e4b34e086ac95e8218f1ee822a4652c8db5bb19`. The input adapter runs the pinned scanner and writes the exact u16 records from `runs::front` in little-endian order. Both reconstructions consume these files directly. The adapter separately runs scalar MTF and Plain for the column and expected output. The verifier checks every physical record against that independent column and the cost ledger checks all ten historical input geometries. For the small cases the verifier constructs Ψ independently by stable sorting and tests every row in each published interval, including the distinct next atoms at each permanent failure.
