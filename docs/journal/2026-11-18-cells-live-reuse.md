# Cells already chooses an output occurrence when a letter is exhausted

18 November 2026. Second bounded study of reuse in the shipped Cells induction, following #575.

**After locating the mark, the writer can read each rule once.** Cells currently finds the leftmost output occurrence of every long rule, then reads the rules again to expand them there and copy from them. The induction has already chosen a usable occurrence for each rule. Use the parent cut that exhausted the child. This choice is recoverable from two consecutive stored rules, with no change to the constructor. During a reverse scan the writer can place the short factors, assign each long child's destination once, and record only copies still to do. Those commands fit in the rule records just consumed.

On the frozen block this replaces a second scan of **28,710 rules** with **9,628 copy commands**. Across the 233 large Wikidata blocks it replaces a second scan of **8,176,313 rules** with **2,528,876 commands**. A structural audit checked every source against the already-filled part of the marked output, including 903,299 copies from a *later* output address. Both production kernels use the same 16-byte rule writer. The result passes the few-percent relevance screen below. Its effect on machine time remains open. ## What the frozen trace revealed

The frozen block has 899,931 rows and 92,570 cuts. Its 63,860 short products include 38,512 repeated spellings. Only 6,342 repeats have both the same surviving front and the previous cut's same physical operand pair. Elsewhere in the same trace, 38,306 references to unmarked long rules feed the writer's minimum-position calculation. Each of the 28,678 distinct unmarked long rules already has exactly one parent that consumed its last interval rows. This second count suggested examining **which output occurrence needs to be known at all**.

This question begins with the actual right-end induction. E exhausts both fronts. T exhausts the bottom front and retains the top. B exhausts the top and retains the bottom. Each cut writes a new word consisting of the top word followed by the bottom word. Both kernels give a fresh identity to every stored rule. The independent reviewers of #575 established where identical *spellings* can share a descriptor and why the corresponding interval translations still differ. Here all cuts, translations, words and rule identities can be retained. What changes is the calculation of their output destinations. ## The last use is visible twice

**Consecutive uses.** Once a letter first participates in a cut, it stays on that same front for every subsequent use. A strict win keeps it there and makes the next cut use it again. A loss or equality exhausts it. A closure cannot intervene after a strict cut. Thus its uses are consecutive, all in one operand position. In particular the cut type certifies, before constructing the parent, whether that child is used again.

Call the parent at the last use the child's **owner**. For a rule child there is also a certificate in the ordinary stored grammar. Compare its descriptor with the descriptor on the same side of the **next stored rule**. Equality means that the child survived. Inequality, including the end of the array, means that this is its owner. Indeed, if a rule child survives, its very next parent contains that same rule, so the next logical cut necessarily produces a stored rule too. Conversely a dead rule identity cannot reappear. This includes short *marked* products that Cells keeps as rules. Cuts that produce an unmarked short word have no entry in the stored rule array. Such a cut cannot intervene while a rule operand survives. A reverse scan can retain the later descriptor pair in two registers. No extra bit, list of parents, width comparison or dictionary is needed in induction. This certificate uses the shipped rule identities. Interning equal long words across distinct letters would require a new ownership certificate.

**Freedom to choose an occurrence.** Unfold the rule grammar of the marked root. Occurrences of a fixed rule identity have disjoint positive-length spans. Two overlapping spans in this parse tree would be nested, which would make the same rule its own strict descendant. Creation order forbids that. Select one incoming occurrence for each reachable nonroot rule inside a selected parent occurrence. Expanding the rule there gives a complete source for every other reference to that rule. Child-before-parent copy order suffices even if the source has a larger address. This explains exactly which information the old minimum computes in excess.

**When the last-use choice works.** Let $p$ be the marked cycle length and $n$ the input block length before RLE1. The sum of remaining interval width times word length is initially $n$ and is conserved by each cut. A closure removes positive mass. If $p=n$, the marked singleton's final word accounts for all the mass. Every rule contributes to it. Following owners strictly increases the rule's birth index and reaches the marked root. These edges therefore form a rooted tree spanning the rule identities. A cut has at most one surviving child, so each parent has at most one long reference outside this tree. This proof applies to every full-period block. All 233 Wikidata blocks and all six published prose controls in this study have full period.

## A schedule with one rule scan

Use the usual walk down the marked children to find the rotation. Place the root at the corresponding circular output offset. Then scan the stored rules from last to first. At a rule with position $q$ and children $a,b$, their destinations are $q$ and $(q+|a|)\bmod p$. One comparison and at most one subtraction suffice. A wrap occurs only on the marked path. Cutting one byte past the mark leaves every unmarked factor contiguous in the physical output.

1. For an arena word or singleton byte, write its advertised bytes at its destination.
2. For a rule child whose current parent is its owner, assign the destination to the child. This is its only position assignment.
3. For a surviving rule child, append a deferred command containing its existing descriptor and this destination. The source position may still be unknown.

Each parent generates at most one command. Store the commands from the high end of the already-read rule array downward. After $k$ parent records have been read, at most $k$ command records occupy their space. A 64-bit child descriptor and 32-bit destination fit in a 16-byte record. Both original children are in registers before any overwrite. At the end the compacted suffix is already in increasing parent birth order. Scan just that suffix, reading the chosen child position and performing the copy. There is no sort or second list allocation.

**Why every source is ready.** After the reverse scan, the short factors and the destinations reserved for deferred copies partition the marked period. Consider a command created by parent $j$ for child $c$. Any unfilled piece inside the selected occurrence of $c$ is a command of $c$ or of one of its descendants. Its creating parent is strictly earlier than $j$. Induction over the forward command scan therefore gives a completely filled, disjoint source on each copy. A rule referenced $k$ times still accounts for one expansion and $k-1$ copies of the same length. Copy volume, the marked byte, the rotation and the existing RLE1 handoff are preserved. [Executable schedule and coverage checks](2026-11-18-cells-live-reuse/positions.py)

**Two sharp examples at the shipped 16-byte cutoff.** The column $L=11\,0^{33}$ with primary 2 has one cycle. A 17-byte word can be copied from offset 17 to offset 0 after the source has been filled. The nearby column $L=11\,0^{34}$ with primary 3 has period 18 in 36 rows. Rule 0 spells 17 bytes. Marked root rule 1 references it on a bottom win, and unmarked rule 2 exhausts it at equality. Rule 2 lies outside the marked root. Choosing its occurrence would leave reachable rule 0 without a source.

For $p<n$, use the ordinary reachability pass. There is still a smaller exact saving. Overwrite a child's position with **any reachable parent's offer**, retaining the NIL test for unreachable parents. At the time the child itself is visited, every reachable parent has already offered its settled position. The existing forward expansion with its equality test works from the chosen sources. This removes the old-position read and minimum per reachable long offer. The simpler fallback of using the shipped writer also preserves correctness. The full-period test costs one predicate per block.

A repeated physical pair outside a shared front necessarily consists of two literals. A nonliteral has a unique physical identity and all its uses take place during one front tenure. At frozen step 4, two new sites make the same literal pair as at step 1. At step 106 the product has the same tree as an earlier three-byte word, with a different child handle. These are different occurrences of one derivation. The zero different-tree counts agree with the standard Lyndon factorization identified in the earlier research. They say nothing about the cost of finding an earlier descriptor. Recognizing the 5.90 million equal-tree cases just from child identities would require previously establishing those children's equivalences. The live scalar handles do not supply that premise. ## What can share #575's lookahead?

**Word forwarding.** On an untouched bottom refill after T, the retained winner, the old and new bottom handles and the previous product suffice to recognize a repeat before the next construction, including TT. On Wikidata, 1,214,986 short TT products satisfy this certificate in addition to #575's 650,507 mixed products. Together they account for the entire first row of the duplicate census. One carried product suffices along overlapping streaks. The lazy source dispatch already distinguishes the untouched entries. The eager kernel has the same geometric certificate but pays to select its literal probes. Even the whole adjacent family comprises 6.80% of the word constructions. Applying the review's generous 10–25% saved fraction per average induction step at a 50% phase share gives 0.34–0.85% of kernel time before overhead. The 273,731 older same-front cases would add under one percentage point of step coverage even with perfect recognition. [Lookahead prices](2026-11-18-cells-live-reuse/cost.md)

**Boundary forwarding.** During consecutive wins of one side the outer previous link of the winner's unconsumed interval is invariant. The scalar T writes that link into the next promised bottom slot, then the next T reloads the very field it just wrote. BB has the mirror identity on top. Retaining the field in one register removes a load on 32,273 frozen cuts and 9,699,621 cuts across Wikidata. The certificate is the previous and current cut direction. It applies in eager and lazy Cells, independently of word equality and without lookahead. At frozen step 3,314 a direction switch would forward 0 where the other order requires 715 in the symbolic slot model. The removed load is a same-worker read of a just-written field. It represents 2.15% of frozen eager induction reads and 1.55% of lazy induction reads in the baseline profile. On the narrower 1,218,876 untouched TT lookaheads, the already-known second T also permits omitting the transient slot store. This is an extra store saving on those pairs only. The output-position result uses neither lookahead nor equal-word detection. Its advantage comes from knowing *which occurrence will do* while the interval is still live, and from finding that choice preserved in the ordinary grammar. That is the bounded study's positive result. The evidence supports independent review of the schedule and its cost model. Production speed remains an experimental question.
