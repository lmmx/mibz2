# Cost of choosing a representative

The [study](../2026-11-18-cells-live-reuse.md) proves correctness. This ledger prices the production 16-byte rule representation shared by eager and lazy Cells on full-period blocks. Its unit is one addressed scalar field read/write (32 or 64 bits), register arithmetic operation, move, or predicate with its conditional successor. A field access includes its base/index addressing. Loop-edge register renaming is free. Byte-copy payloads are accounted for separately. The ledger compares work at the source level. Instruction fusion, spills, cache lines, memory-level parallelism and elapsed time have no fixed price in this model.

## Counted objects

Let $R$ be all stored rules, $M$ marked rules and $U=R-M$ unmarked rules. Let $J$ be references to **unmarked rule** children from any parent, including parents on the marked spine. The spine has $M-1$ marked rule-child edges and ends in a marked singleton. Each unmarked rule has one owning edge. There are $K=J-U$ copy commands. These are exactly the edges of this kind at which the child survived the cut. Every stored parent has at most one such child. Parent references are counted by physical rule identity, regardless of equal spelling or equal lengths.

The constructor, admission, mark-location walk, rule arena, position table capacity, output length, literal lengths and long-copy lengths are common. Over all 233 Wikidata blocks both schedules emit 48,080,312 literal bytes and copy 161,617,350 bytes within the output. The changed schedule still needs the production position slot for each rule. The commands overwrite only already-consumed rule records. A caller needing the grammar to persist would have to pay for a separate command array. In the shipped path the writer is its last consumer. The test program makes a copy for comparison with the original.

## Memory references

| Operation | Shipped writer | Owner schedule |
|---|---:|---:|
| Read two 64-bit operands per rule visit | $4R$ | $2R$ |
| Read the current rule's output position | $2R$ | $R$ |
| Read the previous candidate for an unmarked child's position | $J$ | 0 |
| Store a position | $J$ | $R$ including the root |
| Look up a source position during expansion | $J$ | $K$ |
| Store and reload a command's descriptor and destination | 0 | $4K$ |
| **Total** | **$6R+3J$** | **$4R+5K$** |

For the first row, an unmarked rule has two main-loop visits in the shipped writer. A marked rule instead has two spine visits after locating the mark. Both main sweeps read the position even for marked rules, whose position is NIL. The owner schedule includes marked rules in its ordinary scan. A command holds a 64-bit descriptor and a 32-bit destination, so a stored command and its subsequent load account for **four** field accesses. The parent-rule arena gives 16 bytes of stride if desired, and only 12 are read or written. The corresponding counts in *addressed field bytes* are $40R+12J$ and $24R+28K$. They exclude output payload accesses and physical cache transfers. The old table clear, up to $4R$ additional bytes, is omitted from both prices. Keeping a safety initialization on both paths would preserve this comparison.

## Control, arithmetic and failed recognition

The following price deliberately credits a subset of old operations and allows extra work on the new path. Both programs process a rule by obtaining its children, extracting fields and forming a right destination. We cancel one rule-scan advance and one ordinary right-destination addition per rule. The original forward sweep already needs that addition, and each marked rule's spine processing needs it as well. The candidate's extra range correction is charged below. Displacement arithmetic for an addressed field belongs to that access. The base address of the output and the rule range are block constants.

| Charged scalar work | Shipped writer, credited floor | Owner schedule, allowance |
|---|---:|---:|
| Reachability tests, child classes, and choice of source | $2R$ NIL tests, $4U$ child class tests, $2J$ minimum/comparison operations | $2R$ child class tests and $J+M-1$ tests against the later same-side descriptor |
| Length and cyclic destination | Further baseline savings omitted | Two length masks per rule, one wrap test per rule and up to $M$ actual subtractions |
| Carry both later operands | 0 | Two register moves per rule |
| Command bookkeeping beyond the field accesses | 0 | Up to $5K$ for two cursor advances, the forward loop test and two extra operand/destination moves |
| Block setup and termination beyond common work | 0 | 12 units |

For W16, the writer can distinguish an arena item from a rule by its reference relative to the rule region, also for a marked short rule and for the marked singleton. A width decision or future-step lookup adds zero work in induction. The later operand comparison is charged even when it fails, including the many children with a unique parent. The two carry moves are charged even if alternate loop registers eliminate them. The model includes the full-period guard. The other block setup allowance covers forming the root coordinate from the known rotation, setting up the command cursor and the neighboring operand pair, and the two terminal loop edges. Cell width, live intervals, budget, frontier materialization and fallback admission keep their normal costs.

Thus the comparison is $6R+3J+2R+4U+2J$ against $4R+5K+7R+(J+M-1)+M+5K+12$. On frozen this gives **535,922 versus 450,471**, with exactly 15 wraps against 32 charged. The full corpus totals are **151,568,927 versus 125,944,041**. The smallest margin on any Wikidata block is 76,157 units. Under this accounting the smallest blockwise break-even surcharge is **2.719 units per rule**. Pricing three independent fields per command in both directions adds $2K$. Even that charge alone leaves positive margins on all 233. Extra spills or costly scattered writes can change the sign on a real processor. [Recompute the prices](prices.py) · [Inputs](blocks.csv)

## Other reuse families

**One product across consecutive cuts.** After an ordinary T the opposite front must be read. If the old and new operand descriptors agree and the first result is a plain arena word, the next result is that descriptor again. It can be forwarded before the next construction, including when that next cut itself wins and forwards it again. The remaining interval widths and destinations keep their own identities. For lazy Cells give the existing untouched-source dispatch one additional unit, and charge two predicates and a descriptor move per untouched refill, including all failures. With $F$ such refills and $H$ successful consecutive repeats, the #575 price of seven units avoided per short join gives $7H-4F$. Frozen gives 18,978 units, the whole corpus 5,569,687. The narrower *additional* TT portion alone gives $7(1,214,986)-4(1,218,876)=3,629,398$ if even the dispatch is charged again. These ledgers describe overlapping operations and must not be added to #575's balance.

Eager Cells can wait for its normal bottom read and guard on the old operand's literal status. This costs one predicate on every T and up to three more operations on each T with a plain old literal. The pooled forced-trace balance is $7H-7,774,453-3(1,871,765)=-331,297$. Testing every refilled pair would be dearer still. The absence of an extra eager untouched tag matters. A pre-existing lookahead can supply descriptors to several checks, but cannot make an eager probe free. For older same-front matches, the current geometry names the winner and the opposite operand. It does not point to the earlier result after intervening cuts. Even granting a free remembered result for all 273,731 cases would recover only 1.00% of all steps' word constructions. The previous ring experiment prices the risk of a general history lookup.

**Direct literal-pair address.** The underlying equality is exact before construction, for either kernel. Consider a fixed catalogue $D$ of the 65,536 byte pairs laid out at two bytes per entry, plus padding for a 16-byte read. A pair of canonical literal references $h_a=L+a,h_b=L+b$ names an entry at $D-514L+2(256h_a+h_b)$. Precompute the bias. Allow initialization once per worker and thereafter charge one sum-length-equals-two predicate on each short construction. Computing the address takes two shifts and two adds in this model. On a hit credit the four 16-byte source/destination operations and the arena advance. The ordinary length sum, short classification and final descriptor are still needed. For $P$ digrams and $S$ short constructions the balance before catalogue initialization is $5P-4P-S=P-S$, negative on every Wikidata block. At minimum the catalogue also needs 131,072 bytes written once, plus padding and its generation or copy. Ordinary descriptors make downstream restoration free. Machine addressing can combine arithmetic, so this rules out this price and layout as a basis for the study. It gives no lower bound on arithmetic encodings.

**Repeated previous link.** A strict T reads $h$ from the promised bottom slot, stores $h$ at the old bottom front and makes that slot the next promise. If the next step is T it reloads exactly this field. The intervening bottom read settles or reads its own new front. A fresh bottom settlement initializes a *top* previous link and the stream tag. No intervening write alters the promised bottom previous field. BB has the same proof with the orders interchanged. Eager Cells does no lazy settlement. One 32-bit register and three control continuations (whole, top retained, bottom retained) suffice. No new width test is required. The [slot checker](boundaries.py) keeps the scalar slot writes and reads the old field only as an independent assertion on hits.

Let $V$ be the strict cuts and $C$ the TT and BB transitions. Credit one avoided read per $C$ and charge one register move for retaining the loaded value at each of $V-C$ starts, including length-one runs. The balance is $2C-V$, or 23,159 on frozen and 7,100,871 over Wikidata. In an implementation charging an extra dynamic dispatch on *every* strict cut the saving would disappear. With an existing untouched TT lookahead, both the intermediate store and its reload may be omitted. The untouched refill sees its stream entry and its own new slots, the second T writes the completed bottom record, and the old $h$ reaches the next promise directly. Consecutive TT links can forward the same $h$ down the streak. Relative to simple forwarding only the store is additional. Across all 233 this subset is 1,218,876 of 9,699,621 forwarded-link hits. Eager use of a preread slot must still exclude an alias, and its selection cost is separate. The writer result uses none of these probes.
