# Independent source audit: compact30 direct constructor

**Disposition: PASS — frozen implementation `e003a327cce7a6228316c8c8070a6c61a4110ab7`, baseline 64-bit x86-64.** No material correctness or memory-safety defect was found in the reviewed constructor. It is suitable to proceed to the **separately registered construction-cost experiment**; this is not authorization to integrate the representation into the production decoder or a statement about its performance.

**Audit boundaries.** Read the complete [331-line handoff](https://github.com/lmmx/mibz2/blob/6a097d8/docs/journal/2026-11-03-compact30-constructor-review-handoff.md), all 1,963 source lines of [`examples/c30walk/ctor.rs`](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs), the parent [`examples/c30walk.rs`](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk.rs) for the frozen `Rec`, `RawG`, `phi`, oracle and walk conventions, the design/brief, and the stored correctness/Miri logs. Source blob SHA **`73b3179604b84a95ebbe1dff1b5000419f8d3c7c`**; handoff blob SHA **`080a16f34fdb7e0dace1f4e06923c52dbfcddf9e`**. These conclusions concern the pinned source, not a mutable branch head.

**What was not done.** There is no Rust compiler or cargo in this audit environment; I did not compile or execute the Rust source, run Miri, change the repository, run performance measurements, or use the i9. As independent supplementary evidence, I built an instrumented Python state-machine implementing the relevant record/cursor/RAW transitions and an *independent counting-scatter oracle*, and ran its no-timing assertions. That is **not** an execution of `ctor.rs`, and cannot prove Rust pointer provenance or compiler behavior. The author's archived test logs were inspected rather than independently replayed.

## Findings requiring attention

No triggering input was found for memory corruption, uninitialized-memory exposure, incorrect canonical output, panic or nontermination in **reachable states of the frozen constructor**. The following are bounded validation or defensive-code observations, not blocking findings:

The canonicalization observation is not a claim that malformed **external counts** can create duplicate RAW indices. They cannot: overfull buckets reject before writing and underfull buckets reject at completion, both before exposing the arena. The duplicate-index concern presupposes a violation of an internal invariant for which the reviewed source has no construction path.

## 1. Uninitialized `Rec` arena and `set_len`: source-level sign-off

**Locations:** [`build`, 719–803](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L719-L803), [`W` methods, 320–649](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L320-L649). The parent defines `Rec { f: [u16; 30], h: u32 }` with 64-byte size/alignment and `h` at byte 60, and `RawG([u32; 32])` with 128-byte size and 64-byte alignment ([parent lines 73–92](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk.rs#L73-L92)). There is no struct padding within the recorded 64 or 128 bytes.

**Destination invariant (the essential proof).** For each byte `c`, let `a_c = Σ_{d<c} counts[d]` and `k_c` be the number of `c` rows already consumed from the source. The stored cursor is exactly `x[c] = φ(a_c + k_c)`, with immutable limit `xl[c] = φ(a_c + counts[c])`. Here `φ(r) = 32⌊r/30⌋ + (r mod 30)`. The scalar advance at line 607 skips labels 30/31. For a run of `m` rows, with `j = x[c] mod 32`,

`φ(a_c + k_c + m) = x[c] + m + 2⌊(j+m)/30⌋`,

which is the computed `x_end` at lines 539–546. The check `x_end <= xl[c]` or scalar `x[c] < xl[c]` precedes every write. Since the nonnegative count buckets partition `[0,n)`, every written destination lies in an actual row label, never a header label, and has group index `< G = ceil(n/30)`. The checks still work when the supplied counts disagree with `L` because the *claimed* bucket remains a bounded interval. Overfilled buckets reject on the first excessive row/run; if another bucket is underfilled, the final `x == xl` at line 902 rejects. No partially built record array is published.

**Source invariant.** `y = φ(i)` and `p = i mod 30` for the next source index `i`. `advance(k)` updates both, accounting for the single possible 30-row wrap; the complete-group path advances `y` by 32 for each 30 source rows and leaves `p` unchanged. The 30 immutable patterns implement `φ(i+t)-φ(i)` for all `0 <= t < 30`. This preserves correct labels without a source successor array.

**No read-before-write.** Before source scanning, every bucket-crossing group is made RAW with a **fully initialized** `Rec` and zeroed `RawG` *before* its bit is set (lines 360–375, 838–864). A non-RAW group lies wholly inside one count bucket. The cursor for that byte reaches slot 0 before any later slot, and the slot-0 writer initializes the header and first field. A later `header(g)` read is therefore preceded by the same build's header write; a `promote` read of fields `0..j` is preceded by all those sequential field writes. Forced RAW groups follow the same initialization order. No source path reads an old arena header or field.

**Publication.** At success, each bucket cursor equals its endpoint, hence all `n` row slots have been written once. Every RAW group had all 30 fields and its header initialized at RAW creation. Every ordinary group had its header and every used field written; lines 784–790 fill the final group's unused fields with `0xFFFF`. Lines 791–794 write the extra PARK record. Canonicalization changes initialized headers only. The **only** `rec.set_len` in the module is line 802, after these operations. Both arrays were `clear()`ed before validation; a rejection leaves `rec.len()==0` and `raw.len()==0`, although old bytes can remain in inaccessible spare capacity. A subsequent valid build resets the bitmap and overwrites each published element.

**Testing:** archived large suites report byte-identical `Rec`/`RawG` buffers, including unused fields, RAW padding and PARK; Miri small cases report no uninitialized access. The instrumented independent model checked all abstract header and field reads and all publication slots, including malformed and changed-size cases. **Unresolved:** only the usual gap between source proof, a model, and executing wide promotion in actual Rust under Miri.

## 2. Release-mode raw pointers and arithmetic: source-level sign-off

**Unsafe operations inventory (constructor half):** `header` uses `dst.add(g).h.read` (328–331); `set_header` and `fields` use `dst.add(g)` (335–345); `create_raw` and `promote` replace a complete record via pointer `write` (369, 399), with promotion reading only earlier fields through `f.add(t).read` (396); `fragment`, `complete`, `complete_checked`, and `one` write fields/records at destinations derived from checked encoded cursors (436, 457, 489, 516, 616, 629); final padding and PARK are written at known indices (786–794); canonicalization reads/writes headers for bitmap-set groups (667–671). No `get_unchecked` is used; `raw` and `bitmap` use bounds-checked access.

**Checks optimized out in `build::<false>`:** `g < g_count`; no second `create_raw`/`promote` for an already RAW group; `1 <= j < 30` during promotion; fragment `j+k <= 30`; `g+whole <= G`; and ordinary header byte `h as u8 == c`. These are `chk!` calls (macro 297–302) that become `debug_assert!` in the uncounted release build. All follow from the cursor and group-ownership invariants above, rather than from the assertion executing. The record pointer is taken after all record-vector allocations; no later operation can reallocate that vector before `set_len`. RAW pushes can reallocate only the *different* `raw` vector, not `dst`.

**Arithmetic:** `x+m+2q` fits well inside `u32` because `n <= 983,010` and both `m` and the starting cursor are bounded; header labels fit 20 bits, with ordinary `h < RAW_BIT`. Successor labels within a single byte bucket grow with source index, so `y-(h>>8)` is nonnegative. The last pattern offset bounds earlier offsets: `d+pat[k-1] <= 65,533` implies each `u16` sum written at line 457 fits and cannot collide with `START=0xFFFE` or `RAWF=0xFFFF`. Source reads through `rd(ll,i)` are made only for 16-byte chunks entirely within `ll` (867–900). Every `Rec` field write is aligned (`64`-aligned base, `u16` field); every header read/write is `u32`-aligned (offset 60).

**Testing:** the counted and uncounted builds were both compared against the oracle under release tests. The independent cursor identity probe verified 9,405 `(start,m)` pairs, and the state-machine model checked destination and phase bounds through run and scalar paths. **Unresolved:** no direct Rust execution in this audit; no approval for 32-bit targets (see platform qualification).

## 3. RAW promotion and offset limit: source-level sign-off

**Locations:** [`fragment`, 421–477](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L421-L477), [`one`, 600–648](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L600-L648), [`promote`, 377–414](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L377-L414).

Promotion is only called after an **ordinary** group has already received `j >= 1` fields. The fragment tests the last prospective successor label before writing any of the new fragment; the one-row path tests its next offset similarly. Since source labels grow and destination slots within a byte bucket are assigned in increasing source order, the last prospective offset is the maximum. Offsets `<= 65,533` remain ordinary; an offset of `65,534` or greater triggers RAW promotion. A promoted group reconstructs exactly fields `0..j−1` with the previous header's base and byte, creates a zeroed `RawG`, rewrites all record fields as `RAWF` with a provisional RAW header, sets the bitmap, then writes the new rows through the RAW writer. No partially written overflowing offset is truncated into `u16`.

After promotion, both scalar and fragment paths find the RAW header and never call `promote` again. Natural complete-group writes cannot overlap an already touched/promoted group: they begin at destination slot 0, and an existing partially filled group has a cursor strictly beyond slot 0. Forced builds use `complete_checked` and route pre-marked RAW groups through the RAW writer.

**Testing:** archived full release suites exercised 2,906 wide promotions in the synthetic suite, all prefix lengths 1–29 through both routes, and 21 examples each at exactly 65,533 and 65,534. Our independent model compared full records against an independently generated `psi`/F oracle at offset targets 65,530–65,538 (43 cases, including 65,533 and 65,534) and recorded 21 promotions. **Unresolved:** the archived Miri run exercised **zero** wide promotions. This is a significant evidence boundary, **not an observed defect or an unproven source offset bound**.

## 4. RAW canonicalization: source-level sign-off

**Location:** [`canonicalise`, 650–702](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L650-L702).

Each crossing/forced RAW group is created once by `create_raw`; each ordinary group becomes RAW at most once via `promote`. Both functions choose the provisional index from the old `raw.len()`, append exactly one zeroed group and then mark exactly one new bit. Thus the set bits identify a **bijection** between group indices and provisional RAW indices. In increasing group order, `canonicalise` writes each group's desired rank into word 31 of its provisional `RawG`, patches the header to `RAW_BIT | rank`, and then applies the resulting permutation by moving a carry through each disjoint cycle. The cycle returns to its starting index because the destination ranks are a true permutation, so all cycles terminate and every group arrives at its correct rank. Word 30 starts zero and is never written; word 31 is zeroed for every group at lines 697–700. The RAW fields `0..29` are never altered internally by `canonicalise`; whole groups are swapped only.

**Testing:** archived isolated `canon_tests` covered 48 cases, with fixed, reversed, rotated, pair-swapped, random, and one-cycle permutations up to 1,200 RAW groups, checking every RAW word and ordinary group. Our independent model checked 50 more constructed permutations (including zero RAW groups, a maximum length 1,200, and full cycles). **Unresolved:** the runtime's rank-count assertion alone cannot establish permutation uniqueness; that obligation is discharged by the creation-path proof, not by the release check. See the nonblocking finding above.

## 5. Reuse, capacity growth, malformed input: source-level sign-off

**Locations:** [`build`, 719–804](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L719-L804), [`scatter`, 837–903](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L837-L903).

On every call, `rec.clear()` and `raw.clear()` precede validation. On successful validation, the constructor grows buffers before acquiring any raw destination pointer and clears/resizes every bitmap word to zero. Every accepted build writes exactly its own `G+1` record elements, then sets length. A smaller next block cannot expose leftover records beyond the new length. `raw.push` initializes new entries and uses safe vector growth even if the reservation estimate is low; growth cannot invalidate the separately allocated record arena. Forced RAW configurations reserve G groups and use the checked complete-group path.

A malformed count vector whose sum differs from `n` is rejected at line 722. With the same total but the wrong distribution, every actual row of byte `c` must fit the count bucket; an overfull byte aborts at `one`/`run` before its offending write, or a left-short bucket makes the `x == xl` finish check fail. Rejected builds have empty exposed arrays, even if some spare-capacity bytes were touched. A previous rejected call may leave the private bitmap unchanged if validation rejects early, but the next validated call always resets it, so there is no stale-state read.

**Testing:** the archived synthetic class includes repeated size sequences 900,000 → 1 → ... → 0 and malformed counts. Our model rejected 110 equal-total malformed count cases, including sizes 70,000, and compared 10 large/reuse-shaped valid cases through maximum `n=983,010`. **Unresolved:** the uncounted empty build lacks a dedicated harness test; 32-bit malformed arithmetic is outside this approval.

## 6. Correctness harness and independence: adequate, with explicit limits

**Locations:** [`diff`, 915–944](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L915-L944), [`check_block`, 1052–1133](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L1052-L1133), [`synthetic`, 1368–1790](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L1368-L1790), [`canon_tests`, 1796–1907](https://github.com/lmmx/mibz2/blob/e003a32/examples/c30walk/ctor.rs#L1796-L1907).

The oracle **is not the direct constructor with different flags**: it explicitly computes the full row-indexed `psi` array from the cumulative counts and the last column, then classifies records afterward. The candidate generates those records with encoded cursors, run coalescing, fragment writes and promotion, then reorders RAW groups. The harness compares both buffers in length and **all bytes** after counted and uncounted builds, checks classification counts, compares the candidate walker with production output and oracle walker output including 14 transition counters, and re-compares after marker restoration. This supports equivalence more strongly than output-only testing.

I fetched the archived console files rather than treating the journal's summaries as free-standing evidence: [`synthetic.console`](https://github.com/lmmx/mibz2/blob/6a097d8/docs/journal/2026-11-03-compact30-constructor-prototype/synthetic.console) reports **174,591** cases (341,014 record comparisons, 511,521 walk output checks), coverage of all 30 complete phases and 71/71 reachable fragment shapes, and 2,906 promotions; [`corpora.console`](https://github.com/lmmx/mibz2/blob/6a097d8/docs/journal/2026-11-03-compact30-constructor-prototype/corpora.console) reports 1,513 corpus blocks checked under four configurations (6,052 block/configuration checks); [`adversarial.console`](https://github.com/lmmx/mibz2/blob/6a097d8/docs/journal/2026-11-03-compact30-constructor-prototype/adversarial.console) reports 528 blocks across configurations. [`miri-quick.console`](https://github.com/lmmx/mibz2/blob/6a097d8/docs/journal/2026-11-03-compact30-constructor-prototype/miri-quick.console) reports exit 0 and **942** small cases with **zero** wide promotions. These are archived author-run logs, **not independently rerun** here.

Blind spots: both oracle and candidate use the same `phi`, format constants, `mix` predicate and walker infrastructure, so shared errors in the *frozen representation* might survive comparison. The production decoder output supplies a different reference for actual decoded text. Poisoning uses one 0xA5 pattern and is not applied after a new allocation; it is supporting evidence only. The Miri cases all have `n < 65,536`, do not enter the segmented room walk, and cannot exercise wide promotion; assertions in Miri's debug build are not evidence that the same `chk!` assertions run in release. The full release tests **did** exercise `build::<false>` with its checks compiled out. Standalone canonicalization tests use valid permutations, not corrupted headers; rejecting invalid internal state is not part of its unsafe contract.

## Independent probes and reproducibility

- [`independent_invariants.py`](independent_invariants.py): a separately written, instrumented *Python mathematical/state-machine model* of the cursor, record, RAW and canonical ordering transitions, checking abstract first-writes and read-before-write hazards, and compared with its own direct counting-scatter oracle. It models malformed distribution counts, forced-RAW configurations, maximum-size and partial records. It is **not Rust**, does not claim Miri-level safety, and does **not** test speed.
- [`independent_checks.json`](independent_checks.json): recorded output, all assertions passed: **9,405** exact cursor identities; **1,092** valid small-oracle comparisons; **110** equal-total malformed count rejections; **43** boundary cases around 65,533 and 65,534; **50** isolated permutation tests; **10** maximum-size/reuse-shaped cases. Instrumented state transitions include 21 wide promotions, 9,435 RAW creations and over 3.3 million abstract header reads checked against initialized state.

No raw-pointer out-of-bounds access or unwritten-field exposure was found in the reviewed source. The invariant proofs are structural, not dependent on the test totals. The remaining nonblocking gaps should be recorded in the future benchmark protocol or follow-up validation plan, but **do not require changing this frozen implementation before a separate construction-cost measurement**.

**Final disposition: PASS** on `e003a32` for the stipulated baseline 64-bit x86-64 research build; authorize protocol design and, once separately approved, construction-cost measurement only. No production integration, walker retuning, representation changes or claim of exhaustive memory-safety verification follows from this verdict.
