# Documentation

The site is built with [Zensical](<https://zensical.org/>) from `docs/site/` and `zensical.toml`. The Python API reference is generated by mkdocstrings from the package's docstrings and the compiled module's stub (`python/mibz2/_mibz2.pyi`).

```sh
just docs-serve   # build, serve and rebuild on change
just docs-check   # strict build, site checks, and the pages' examples as tests
```

- `docs/scripts/check_site.py` checks that every page is in the nav, that internal links and anchors resolve, that every page has a description matching its llms.txt entry, and that every public name is in the API reference.
- `docs/scripts/check_render.py` finds Markdown that rendered as something else (a list run into a paragraph, a stray heading, a flattened nested list), and `docs/scripts/look_pages.py` opens the changed pages in Chromium and screenshots them (`just docs-look`). Before a page is published, its render is read: see the `publish-page` skill in `.claude/skills/`.
- `docs/conftest.py` runs each page's Python examples with pytest (`pytest docs/site`); a `pycon` block's output must match.
- `docs/scripts/bench_history.py` turns the `bench-results` branch into the benchmark pages' data (`docs/site/assets/bench-history.json`) and tables (`docs/generated/`) before each build. Without a checkout of the branch (`--store`), it reads `origin/bench-results`, or writes empty ones.
- `docs/site/assets/data/lane-sweeps.json` holds the measured walk timings by lane count that [Why 32 couriers beat one](<https://lmmx.github.io/mibz2/pr-preview/pr-385/concepts/couriers/#lane-counts>) draws (`assets/javascripts/couriers.js`). It is written by hand, from the record: one panel a sweep, each with its own axes, its points (`x`, `y`, and optionally `lo` and `hi` for an interval) and its source. A new sweep is a new panel; the page draws every panel. Only measured points go in it.
- `docs/site/assets/data/frontier.json` holds the measured series that the [Throughput–memory frontier](<https://lmmx.github.io/mibz2/pr-preview/pr-385/benchmarks/frontier/index.md>) page draws (`assets/javascripts/frontier.js`): throughput against measured peak RSS, and against computed live table memory. It is written by hand, from the record, under the rules in its `about` field. The page's tables give the same values, and stand in for the charts if the script does not run.

## Publishing

`.github/workflows/site.yml` builds the site on every push to master, and after each Benchmark run on master, and publishes it to the `gh-pages` branch, served at [https://lmmx.github.io/mibz2/](<https://lmmx.github.io/mibz2/>). A pull request from this repository gets a preview under `pr-preview/pr-<number>/`, linked from a comment on the pull request and removed when it closes. Previews start once the repository's Pages source is set to the `gh-pages` branch.

Each deploy writes only its own path: production the root, a preview its own directory. Pages rebuilds the branch on every push, and a push that lands mid-build cancels that build, so the next build publishes both. A preview's check therefore waits for the outcome, not for one build: it passes once the preview serves the files of its own run, whose assets carry `?v=<commit>`.
