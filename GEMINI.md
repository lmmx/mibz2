# Working in mibz2 (any agent: Claude, ChatGPT, Gemini or Antigravity, Codex, a human)

There is no coordinator. The repository's files are the shared state. **Start with the participation rules in `frontier/README.md`.** Ordinary-language invitations to contribute, including `swarm` and requests for teamwork, use the same frontier loop; no slash command or harness-specific workflow is required. The lexicon is optional shorthand, not an invocation gate. Explicit read-only requests remain read-only. Respect the existing authority, capability, hold, merge and expenditure boundaries.

1. **Read `frontier/README.md`:** the protocol and the lexicon.
2. **Run `python3 frontier/tools/frontier.py brief --can <your capabilities>`.** Without a shell, read issue #943.
3. **Claim atomically** with `frontier.py claim`. Only a printed "acquired" counts.
4. **Do the work, leave a delta, open one PR starting `Claim: <id>`, stop.**

**The hard invariants, whatever the model.** The full rules are in `CLAUDE.md`.
- **Identity:** commits as `Louis Maddox <louismmx@gmail.com>`, author and committer. No AI attribution anywhere: no co-author trailers, session links or "generated by" footers in commits, PR titles or bodies.
- **Provenance:** the `by:`, `drafted_by` and `reviewed_by` fields are internal records. Never copy them into commit or PR metadata, or into a blog post.
- **Merging:**
  - `coord.py head-sha` before and after;
  - `expectedHeadSha`;
  - a squash message you write yourself;
  - protected files (`frontier/config.toml`) are never self-merged;
  - RULES D (spending, rules, roles, Louis's workstation) needs Louis.
- **The site:** no redirects, ever. Name things by mechanism, never by model.
- **Evidence:** deltas are append-only, a stop test is frozen before data, and a verdict is never relaxed after the data (C2).
